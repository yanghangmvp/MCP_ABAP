# 04 · 作业脚本手册

> `scripts/` 里的 13 个脚本是 **ADT 直连**（不经过 MCP server），用来补 MCP 工具的能力缺口：指定集团查数、跑 SQL、看 ST22、回读文本元素、批量激活、清理探针。
> 它们不改写 SAP 业务逻辑，只提供一条可控、可留档的读写通道。

## 1. 前置条件

| 项目 | 说明 |
|---|---|
| Node.js >= 22 | 与 MCP 包一致 |
| `portable/node_modules` | 脚本通过 `require.resolve` 复用 MCP 包的 `axios` / `@mcp-abap-adt/connection` / MCP SDK。仓库**不含**依赖：把 `releases/*.zip` 里的 `node_modules` 解压到 `portable/`，或 `cd portable && npm install --omit=dev` |
| `portable/env/dev.env` | 由 `node install.mjs --name=dev ...` 生成；也可用 `SAP_ENV_FILE` 指向别的文件 |
| 直连 SAP ICM | 脚本已统一 `proxy: false` 并剥掉代理变量 |

路径自适应（所有脚本通用，无需改代码）：

```js
REPO_ROOT        = process.env.MCP_ABAP_ROOT || <仓库根>
MCP_ROOT         = process.env.MCP_PROJECT   || <REPO_ROOT>/portable
DEFAULT_ENV_FILE = <MCP_ROOT>/env/dev.env     // 可用 SAP_ENV_FILE 覆盖
```

也就是说：脚本可以放在任意目录，只要用 `MCP_PROJECT` 指向含 `node_modules` 的 MCP 包目录即可。**所有绝对路径与客户专属对象名都已泛化为 `ZMY_*` 占位。**

## 2. 通用环境变量

| 变量 | 作用 |
|---|---|
| `MCP_ABAP_ROOT` | 仓库根（脚本与 `portable/` 不在同一目录时用） |
| `MCP_PROJECT` | MCP 包目录（含 `dist/` 与 `node_modules/`） |
| `SAP_ENV_FILE` | 连接配置文件，覆盖默认的 `portable/env/dev.env` |
| `SAP_CLIENT_OVERRIDE` | 临时切集团（**只用于查数 / `$TMP` 探针**，改可传输对象不要用） |
| `SAP_LANGUAGE_OVERRIDE` | 临时切登录语言 |
| `CORR_NR` | 传输请求号（**父请求号，由项目方提供**） |
| `PROG_PREFIX` | `check_activation.js` 的程序名简写前缀 |

## 3. 脚本清单

| 脚本 | 作用 | 关键参数 | 示例 |
|---|---|---|---|
| `adt.js` | 通用查询 / 运行程序 / 短转储排查 | `query` `run` `table` `dumps` `dump` | `node scripts/adt.js query "SELECT bukrs, butxt FROM t001"` |
| `get_source.js` | **只读**回读现网源码 | `PROG/INCL/FM/CLAS/TABL/STRU/DTEL` + 名称 + `--out=` | `node scripts/get_source.js PROG ZMY_PROG --out=backup/before.abap` |
| `call-adt-tool.js` | 一次性拉起 MCP server 并调用单个工具 | `SAP_ENV_FILE` + `<ToolName>` + `@args.json` | `SAP_ENV_FILE=$PWD/portable/env/dev.env node scripts/call-adt-tool.js GetTableContents @args.json` |
| `push_prog_source.js` | 推报表源码并激活（默认 `$TMP`） | `SRC_FILE` `PKG` `PROG_NAME` `CORR_NR` | `SRC_FILE=/abs/x.abap PKG='$TMP' node scripts/push_prog_source.js` |
| `push_fm_source.js` | 推函数模块源码（LOCK→PUT→ACTIVATE→UNLOCK） | `SRC_FILE` `TARGET_GROUP` `TARGET_FM` `CORR_NR` | `SRC_FILE=x.abap TARGET_GROUP=ZFG_MY TARGET_FM=ZMY_FM node scripts/push_fm_source.js` |
| `push_include_source.js` | 推函数组 include 源码（不激活） | `SRC_FILE` `GROUP_NAME` `INCLUDE_NAME` | `SRC_FILE=lzfg_myf01.abap GROUP_NAME=ZFG_MY INCLUDE_NAME=LZFG_MYF01 node scripts/push_include_source.js` |
| `push_table_ddl.js` | 推已存在表的 DDL 并激活；`NO_ACT=1` 只写不激活 | `SRC_FILE` `TABLE` `CORR_NR` `NO_ACT` | `TABLE=ZMY_TAB SRC_FILE=ddl.txt node scripts/push_table_ddl.js` |
| `read_textelements.js` | **只读**回读文本元素激活版全文（stdout） | `<PROG>` `symbols\|selections` `--active` | `node scripts/read_textelements.js ZMY_PROG symbols --active > backup/te_symbols.txt` |
| `push_textelements.js` | 推文本符号 / 选择文本（PUT + 单独 ACTIVATE） | `TE_FILE` `PROG` `CORR_NR` | `TE_FILE=./texts/ZMY_PROG.json node scripts/push_textelements.js` |
| `check_activation.js` | 列 inactive 对象、比对文本元素 active/inactive | `PROGS` `PROG_PREFIX` | `node scripts/check_activation.js` |
| `set_fm_rfc.js` | 把 FM 改成远程使能（`processingType=rfc`） | `TARGET_GROUP` `TARGET_FM` `CORR_NR` | `TARGET_GROUP=ZFG_MY TARGET_FM=ZMY_FM node scripts/set_fm_rfc.js` |
| `delete_prog.js` | 删除 `$TMP` 探针 / include（删除不需要 UNLOCK） | `PROGS` `INCS` | `PROGS=ZTEST_A,ZTEST_B node scripts/delete_prog.js` |
| `_act_dbg.js` | 打印**完整**激活响应（含 longText 与语法错误坐标） | `OBJ` `OBJ_TYPE` `OBJ_URI` | `OBJ=ZMY_PROG node scripts/_act_dbg.js` |

`push_textelements.js` 的 `TE_FILE` JSON 结构：

```json
{
  "program": "ZMY_PROG",
  "symbols": [["001", "标题"], ["003", "未查询到数据"]],
  "selections": [["P_BUKRS", "公司代码"]]
}
```

## 4. 典型工作流：改一个既有程序

```bash
# 0) 摸底：确认集团、对象归属、请求号
SAP_CLIENT_OVERRIDE=300 node scripts/adt.js query "SELECT mandt FROM t000"

# 1) 回读现网（源码 + 文本元素），以现网为唯一基线
node scripts/get_source.js PROG ZMY_PROG --out=backup/ZMY_PROG_before.abap
node scripts/read_textelements.js ZMY_PROG symbols   --active > backup/ZMY_PROG_sym.txt
node scripts/read_textelements.js ZMY_PROG selections --active > backup/ZMY_PROG_sel.txt

# 2) 本地改源码；文本元素与回读结果逐行人工合并，留档
# 3) 推送（顺序不可颠倒）
SRC_FILE=./ZMY_PROG.abap CORR_NR=<PARENT_TR> node scripts/push_prog_source.js
TE_FILE=./texts/ZMY_PROG.json CORR_NR=<PARENT_TR> node scripts/push_textelements.js

# 4) 验证激活与文本元素，必要时打印完整激活报文
node scripts/check_activation.js
OBJ=ZMY_PROG node scripts/_act_dbg.js

# 5) 清理本轮探针
PROGS=ZTEST_MY_PROBE node scripts/delete_prog.js
```

## 5. 五个使用约束

1. **写操作前先查锁、先留 backup**；`$TMP` 探针与可传输对象用不同的集团口径。
2. `CORR_NR` 用父请求号，缺号停手，不自行创建请求。
3. 文本元素推送**必须先回读合并**，否则会无痕覆盖他人在前台改的文案。
4. 异常只打印 `e.message`——脚本已统一，新增脚本别用 `console.error(e)`。
5. 并行任务各用独立 ADT 会话；批量对象按每批 ≤ 5 个分组，避免超时留下残留锁。

> 未收录的脚本：与客户 GUI 状态配置、业务对象强绑定的批量生成器（如 CUA 生成、业务表建表脚本），它们不具备跨项目复用性，不随本仓库发布。方法论见 [05 · 交付流程与检查清单](05-交付流程与检查清单.md)。

# 03 · 踩坑清单

> 格式统一为「现象 → 根因 → 解法」。这些坑大多**编译不报、激活不报、运行时才炸**，或者更糟：返回成功但静默失效。
> 已剔除客户专属对象名与编号，示例统一用 `ZMY_*`。

## A. 部署与连接（7 条）

1. **现象**：MCP 一直未连接。**根因**：改完 `mcp.json` 只关了窗口、没完全退出应用；或没在连接器页点「信任」。**解法**：完全退出重启 + 点信任。
2. **现象**：`socket hang up` / CSRF 令牌验证失败，表象像「SAP 连不上」。**根因**：`HTTP(S)_PROXY` 指向本机代理，ADT 内网直连被劫持。**解法**：`NO_PROXY=*` + `proxy: false`。
3. **现象**：server 启动即失败。**根因**：`--exposition=readonly,high,low`，`high` 与 `low` 互斥。**解法**：二选一。
4. **现象**：所有业务表查出来都是 0 行。**根因**：连到了空壳集团。**解法**：确认数据所在集团，配多套 `--name` 或用 `SAP_CLIENT_OVERRIDE` 查数。
5. **现象**：创建对象报 `PAK049`。**根因**：`SAP_USERNAME` 大小写与 USR02 不一致。**解法**：改成系统里的大写形式。
6. **现象**：新建对象主语言是 EN，违反 ZH 约定。**根因**：`SAP_LANGUAGE` 不在上游 env 白名单，语言注入器兜底成 EN。**解法**：显式注入子进程环境。
7. **现象**：Windows 解压报「文件名过长」。**根因**：`node_modules` 深层路径 + 长解压前缀撞 260 上限。**解法**：解压到 `C:\tools\`；用 7-Zip；本包已把最长相对路径压到 130 字符。

## B. ADT 写入与激活（9 条）

8. **现象**：PUT 报 `Resource ... is not locked (invalid lock handle)`。**根因**：LOCK/PUT 不在同一 ADT 会话（connectionid 或 cookie 不一致）。**解法**：全程复用同一个 connectionid + 合并 cookie jar。
9. **现象**：CSRF 令牌验证失败，明明刚 fetch 过。**根因**：cookie jar 只存了 value，Cookie 头退化成裸值。**解法**：存整段 `name=value`。
10. **现象**：403 被翻成「对象被锁」，但没人编辑。**根因**：报文其实是 `locked in task ... not specified for this client`，即集团不对。**解法**：换回请求所属集团；换请求号无效。
11. **现象**：激活返回 200，SE80 里仍是旧版。**根因**：只看 HTTP 状态，没看 `final version => active`。**解法**：读完整激活报文；`_act_dbg.js` 可打印 longText。
12. **现象**：激活报错被截断成一句 `<shortText>`。**根因**：MCP 工具只回摘要。**解法**：直接调激活资源拿完整 XML，`href="...#start=行,列"` 就是语法错误坐标。
13. **现象**：文本元素显示黄色未激活，前台看不到新文案。**根因**：文本元素是独立对象 `PROG/PX`，PUT 只写 inactive；激活父程序 `PROG/P` 不连带。**解法**：单独 ACTIVATE `PROG/PX`。
14. **现象**：覆盖推送后，别人在前台改的文案无痕消失。**根因**：用了陈旧 JSON，代码 diff 看不出来。**解法**：推送前回读激活版，逐行人工合并 + 留档。
15. **现象**：`GetInactiveObjects` 列出 `FUGR/F`、`FUGR/I SAPLxxx`。**根因**：函数组主程序的固有形态，不是缺陷。**解法**：以 `ActivateObjects` + `ENLFDIR.ACTIVE='X'` 为准。
16. **现象**：新建 FM 后调用侧参数不可见 / 改结构后表类型失效。**根因**：依赖对象未激活。**解法**：函数组 + FM 双激活；`ActivateObjects` 复活表类型。

## C. ABAP 语法硬约束（8 条）

17. **现象**：激活报 `Field "|" is unknown`。**根因**：字符串模板 `|...|` 直接作 `PERFORM ... USING` 实参。**解法**：先赋给变量再传。
18. **现象**：FORM 形参报 `Numeric literals cannot be used as field names`。**根因**：形参写了 `TYPE c LENGTH n`（`DATA` 里合法，FORM 形参不允许）。**解法**：用 `TYPE char<n>` 或 DDIC 类型。
19. **现象**：`Field "TABLES" is unknown`。**根因**：FORM 形参顺序写反，`TABLES` 必须在 `USING`/`CHANGING` 之前；`PERFORM` 调用侧同理。**解法**：`FORM f TABLES pt USING a CHANGING c.`
20. **现象**：编译期报实参/形参不兼容。**根因**：字符类按引用传参要求实参长度与形参一致；文本符号免编译检查但仍会在运行期 500。**解法**：形参用泛型 `TYPE c`，或先赋同长变量中转。
21. **现象**：`TYPE string` 形参接不住 `CHARn` 变量。**解法**：中间变量中转。
22. **现象**：`concat` 之外怎么写都报错。**根因**：SQL 里 CHAR + NUMC 拼接只能用 `concat( a, b )`，`&&` / `CAST` 都不行。
23. **现象**：`SELECT 368 ... not compatible`。**根因**：显式列清单 + `INTO TABLE` 预定义结构按**位置**赋值，字段错位。**解法**：配 `INTO TABLE @DATA(...)` 让结构由列清单生成，或 `SELECT *`。
24. **现象**：编译期才炸，标识符里看着正常。**根因**：编辑器混入零宽字符（如 U+200B）进了标识符。**解法**：`LC_ALL=C grep -n '[^ -~]' <file>` 快筛，再用脚本剔除。

## D. FM / DDIC 对象（7 条）

25. **现象**：`FUNC_ADT 028 Parameter comment blocks are not allowed`。**根因**：FM 源码里 `*"` 是签名声明区，不是自由注释。**解法**：用 ADT 内联签名语法；普通注释一律 `*`。
26. **现象**：`Parameter IT_X declares no type`。**根因**：`TABLES` 参数写成 `STRUCTURE xxx`。**解法**：写 `it_x TYPE <表类型>`。
27. **现象**：`CTS_WBO_API 019 对象已在用户 ... 请求中锁定`（其实是同一个请求）。**根因**：`CreateFunctionModule` / `CreateFunctionGroup` 没显式传 `transport_request`。**解法**：显式传。
28. **现象**：`CALL FUNCTION` 报完全无关的 `Unable to interpret "EV_XXX"`。**根因**：参数段顺序必须是 `EXPORTING → IMPORTING → CHANGING → TABLES → EXCEPTIONS`。**解法**：调顺序。
29. **现象**：新建 FM 不是远程使能。**根因**：ADT 默认 `processingType="normal"`，且无专门工具。**解法**：整份 PUT 属性资源，媒体类型必须 `application/vnd.sap.adt.functions.fmodules.v3+xml`（`application/xml` 返 406），PUT 的 URL **必须同时带 `corrNr`**。
30. **现象**：建表激活报「维护和保存 X 的技术设置」。**根因**：跳过 `CreateTable`（自带 DD09L）直接建/半途激活。**解法**：`CreateTable` 建空壳 → `UpdateTable` 全量 DDL + activate；已半成品则删表重建。
31. **现象**：`UpdateStructure` 对新对象报 403（被翻成 CSRF 失败）。**根因**：对象不存在。**解法**：新对象一律先 `CreateStructure`；`CreateTableType` 用 `row_type_name`。

## E. JSON 接口与网关（6 条）

32. **现象**：报文里空值字段整批丢失。**根因**：`/ui2/cl_json=>serialize` 的 `compress='X'`。**解法**：`compress` 必须传空。
33. **现象**：金额字段被当成字符串，下游解析错。**根因**：用了 `STRING`。**解法**：金额用 `DEC`，CURR/QUAN 用 `DEC:l,d`。
34. **现象**：`A row already exists with this key`。**根因**：`name_mappings` 唯一键表里同键重复登记。**解法**：只登记推导不出来的键；`pretty_name='X'` 按每层独立推导，嵌套层不要加层级前缀。
35. **现象**：嵌套结构的 JSON 键对不上。**根因**：serialize 查 `abap` 键、deserialize 查 `json` 键，是两张表。**解法**：请求/返回各备一张映射表。
36. **现象**：接口返回 200 + `msg=token已失效...` 却没有 `code` 键。**根因**：网关要 HTTP Basic，缺凭据。**解法**：`cl_http_client=>authenticate( )`；遇「无 code」把原文带回消息字段。
37. **现象**：返回结构少字段却测不出来。**根因**：字段值恰好为空，探针跑通也会漏。**解法**：按 FS 样例做**键级对账**；成功判定别只看 `code`（失败时也可能是 `'0'`）。

## F. F4 / 弹窗 / 探针（7 条）

38. **现象**：点弹窗确认后毫无反应（无消息、无动作、无转储）。**根因**：`POPUP_GET_VALUES` 的 `RETURNCODE` 语义反直觉：**`'A'` = 取消，空格 = 确认且已回填**。**解法**：`IF lv_rc = 'A'. <取消处理> ENDIF.`
39. **现象**：`POPUP_GET_VALUES` 里按 F4 不弹帮助。**根因**：字段没挂住 DDIC 搜索帮助。**解法**：指到有帮助的表字段（会改变长度/ALPHA，慎用），或改用 `POPUP_GET_VALUES_USER_HELP` 自建出口（推荐）。
40. **现象**：自建 F4 出口里选了值但屏幕不刷新。**根因**：出口 FORM 由 FM 以 5 个 `USING` 调用，需把选中值写回第 5 个形参并把 `returncode` 置 `'F'`。**解法**：按此实现；拿不到 `sy-stepl` 就别走 dynprofield 回填。
41. **现象**：`F4IF_INT_TABLE_VALUE_REQUEST` 按 F4 弹不出，`sy-subrc=1`。**根因**：`FIELD_TAB` 每行推不出 `INTTYPE`（只填 `FIELDNAME`/`FIELDTEXT` 不够）。**解法**：`FIELDNAME + DATATYPE='CHAR' + INTTYPE='C' + LENG + OUTPUTLEN`；或传 `DDIC_STRUCTURE` 让 FM 自己填。
42. **现象**：F4 弹得出，但选中/关窗时 DUMP `ASSIGN with length 0`。**根因**：`INTLEN` / `OFFSET` 是**字节**长度，Unicode 下 `INTLEN = 字符数 × 2`；只填 `LENG` 会踩 `convert_result`。**解法**：用 `DESCRIBE FIELD ... IN BYTE MODE` 从同类型实例动态取，别硬编码。
43. **现象**：接口跑出 500，日志里看不出根因。**根因**：没读短转储。**解法**：`node scripts/adt.js dumps` 拿 id → `adt.js dump "<id>"` 读全文，看 `Error analysis` 段的 procedure 名 + `CX_SY_*` 异常类。
44. **现象**：探针入参为 `DEC` 时报 `cannot be interpreted as a number` 并返 500。**根因**：给数值字段赋了字符串字面量。**解法**：数值型入参用数值字面量。

## G. 工程化（3 条）

45. **现象**：批量脚本被超时打断，留下半成品与残留锁。**根因**：一次跑太多对象。**解法**：按 `ONLY=` 分批，每批 ≤ 5 个；脚本带幂等与自检断言。
46. **现象**：补丁脚本生成的文件里关键值全变成同一个残值（如占位符只替换了一次）。**根因**：模板生成缺少断言。**解法**：生成后断言关键值出现次数、禁止残留词计数为 0，断言不过即非零退出、不写盘。
47. **现象**：diff 整文件全红。**根因**：`\r\n` 与 BOM 差异。**解法**：比对前统一换行规范化、去 BOM。

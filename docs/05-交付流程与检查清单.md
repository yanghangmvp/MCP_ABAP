# 05 · 交付流程与检查清单

> 新项目开工照着走一遍，可以避免绝大多数「联调阶段才暴露」的返工。
> 这份清单面向 **AI 辅助的 ABAP 交付**：人定命名与请求号，AI 负责回读、diff、推送、验证与留档。

## 阶段 0 · 摸底（开工当天）

- [ ] 确认系统类型：On-Premise / Cloud；认证方式；ICM 端口（`ping` 通）
- [ ] 确认**数据所在集团**，并明确「请求所属集团」是哪一个（两者可能不同）
- [ ] 确认语言约定（本项目一律 ZH，含 DDIC 主语言）
- [ ] 拿到开发账号、`S_ADT_RES` 权限、父请求号；**不自行创建请求号**
- [ ] 拿到项目命名规范与对象模板（报表 / 批导 / 接口），先读模板再写代码
- [ ] 部署本仓库：`node install.mjs --name=dev ...` → 重启客户端 → `verify.mjs --sql=...` 端到端通过
- [ ] 建立 `backup/` 留档目录；确认 `.gitignore` 排除 `*.env`

## 阶段 1 · 动手前（每个对象）

- [ ] **回读现网源码**：`get_source.js`，以现网为唯一基线（归档只作比对）
- [ ] **回读文本元素激活版**（symbols + selections 各一次），存进 `backup/`
- [ ] 查 `TADIR` / `E071` 确认对象归属、包名、请求号
- [ ] 归档 diff 前统一换行（`\r\n` → `\n`）并去 BOM
- [ ] 确认对象未被锁；确认没有人在 SE80 里同时编辑
- [ ] 命名方案先给人工确认（对象类型 + 建议名 + 同前缀占用清单 + 编号延续理由）

## 阶段 2 · 编码自检

- [ ] 程序头八字段 + 摘要/注意/变更记录齐全；事件五段；`END-OF-SELECTION` 按 `sy-batch` 分流
- [ ] ALV 用 LVC 不用 SLIS；文案一律走文本元素
- [ ] 接口采用「瘦函数体 + FORM」；日志写在 FUNCTION 体内（不要放 include）
- [ ] SQL：`SELECT` 列表逗号分隔；显式列清单配 `INTO TABLE @DATA(...)`；CHAR+NUMC 拼接只用 `concat`
- [ ] FORM 形参：无内联 `TYPE STANDARD TABLE OF`、无 `TYPE c LENGTH n`；`TABLES` 在 `USING` 之前
- [ ] 隐藏字符体检：`LC_ALL=C grep -n '[^ -~]' <file>`，排除零宽字符
- [ ] 返回结构按 FS 样例做**键级对账**（含值恰为空的字段）
- [ ] 金额用 `DEC`、`compress` 传空、`name_mappings` 请求/返回各一张表

## 阶段 3 · 交付四步（顺序固定）

1. 生成源码 →
2. 推源码：`push_prog_source.js` / `push_fm_source.js`（LOCK → PUT → UNLOCK → ACTIVATE）→
3. 推文本元素：**先回读合并** → `push_textelements.js` → 单独激活 `PROG/PX` →
4. 生成 GUI 状态（按项目 CUA 模板）

每一步之后：

- [ ] 看激活返回里的 `final version => active`，不要只看 HTTP 200
- [ ] `check_activation.js` 复核；异常用 `_act_dbg.js` 拿完整报文与行号
- [ ] 新建 FM：`ActivateFunctionGroup` + `ActivateFunctionModule` 双激活；接口 FM 记得 `set_fm_rfc.js`
- [ ] 改结构后引用它的表类型要 `ActivateObjects` 复活
- [ ] `$TMP` 探针跑 E2E，输出留档到报告；日志里不得出现凭据

## 阶段 4 · 收尾

- [ ] 现网代码回读 → 与归档反向 diff → 归档同步
- [ ] 本轮新建的 `$TMP` 测试程序 / 探针 / 临时类表**测完即删**（先留档 → 再删 → 回查 `TADIR`/`TRDIR`）
- [ ] 生产源码里不得出现 `ZTEST_*` 引用；不得把 `scripts/` 工具名写进源码注释
- [ ] 源码注释口径按项目模板：只保留程序头、摘要/注意、变更记录、FORM 横幅、形参文档、标记与短行注释；**不写**设计依据 / 联调实测 / 坑位 / TODO 理由
- [ ] 剥离注释后做 diff：确认**代码本体逐行零改动**
- [ ] 测试报告、留档、请求号清单归档；凭据类文件不进任何交付物

## 常见风险清单

| 风险 | 触发条件 | 预防 |
|---|---|---|
| 覆盖他人在前台的改动 | 拿陈旧归档或陈旧文本 JSON 直接推 | 阶段 1 强制回读 |
| 静默失效（返回成功但没变） | 只看 HTTP 200 / 激活对象类型选错 | 阶段 3 逐项复核 |
| 凭据泄露 | `console.error(e)`、env 入库、日志回显 | 只印 `e.message`；`.gitignore`；600 权限 |
| 残留锁与半成品 | 长批量脚本超时 | 每批 ≤ 5 个对象，带幂等与自检断言 |
| 集团混淆 | 习惯性加 `SAP_CLIENT_OVERRIDE` 改可传输对象 | 铁律 2/3，见 [02 · ADT 写入铁律](02-ADT写入铁律.md) |
| 版本漂移 | 随手升级上游主版本 | 锁 7.0.3，升级前跑工具集回归，见 [NOTICE](../NOTICE.md) |

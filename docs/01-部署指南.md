# 01 · 部署指南

> 面向 On-Premise ECC / S/4HANA + Basic Auth。第一步永远是先确认网络能直连 SAP 的 ICM 端口。

## 1. 前置条件

| 项目 | 要求 | 检查命令 |
|---|---|---|
| Node.js | >= 22（`install.mjs` 会校验） | `node -v` |
| 网络 | 能直连 SAP ICM（HTTP 50000 / HTTPS 44300） | `curl -k https://<host>:44300/sap/public/ping` |
| SAP 权限 | 开发账号 + ADT 资源权限（`S_ADT_RES`），需能读/写 ADT 资源 | SE80 里能建对象即基本满足 |
| 客户端 | WorkBuddy（本方案默认）；任意支持 stdio MCP 的客户端可手动配置 | — |

> **不要先怀疑 MCP，先 ping ICM。** 连不上 SAP 的绝大多数情况是代理、证书或端口，不是 MCP 本身。

## 2. 一条命令装好

```bash
node install.mjs --name=dev \
  --url=https://your-s4-host:44300 \
  --client=300 \
  --user=YOUR_USER \
  --pass=YOUR_PASSWORD \
  --lang=ZH \
  --exposition=readonly,high
```

| 参数 | 说明 | 默认 |
|---|---|---|
| `--name` | 系统标识，决定 env 文件名与 MCP 条目名 `adt-<name>` | `mysystem` |
| `--url` | SAP 地址，含协议与端口 | 交互式询问 |
| `--client` | 集团 | 交互式询问 |
| `--user` / `--pass` | SAP 账号密码；交互式填写时密码不回显 | 交互式询问 |
| `--lang` | 登录语言，影响新建对象主语言 | `ZH` |
| `--exposition` | `readonly,high`（读 + 写）/ `readonly,low`（读 + 系统管理） | `readonly,high` |
| `--env-only` | 只生成 env，不改 `mcp.json` | — |
| `--uninstall` | 从 `mcp.json` 移除该条目 | — |

脚本做两件事：写 `env/<name>.env`（权限 600）、把 `adt-<name>` 合并进 `~/.workbuddy/mcp.json`（**改动前自动备份** `mcp.json.bak.<时间戳>`）。

## 3. 多系统 / 多集团

MCP 工具**不能按调用指定集团**，集团由 env 文件决定。要接多套系统或同一系统的不同集团，就配多套条目：

```bash
node install.mjs --name=dev --url=https://dev-host:44300 --client=100 --user=... --pass=...
node install.mjs --name=qas --url=https://qas-host:44300 --client=300 --user=... --pass=...
```

生成 `adt-dev` / `adt-qas` 两个独立条目，互不覆盖。作业脚本则用 `SAP_ENV_FILE` 或 `SAP_CLIENT_OVERRIDE` 临时切集团：

```bash
SAP_ENV_FILE=$PWD/portable/env/qas.env node scripts/adt.js query "SELECT mandt, mtext FROM t000"
SAP_CLIENT_OVERRIDE=300 node scripts/adt.js query "SELECT mandt, mtext FROM t000"
```

> **先确认数据集团**。实施项目里常见「默认集团是空壳、业务数据全在另一个集团」，查询前用 `SELECT COUNT(*)` 之类的探针确认，别拿空结果当业务结论。

## 4. 手动配置（其他 MCP 客户端）

`~/.workbuddy/mcp.json`（**没有点前缀**）：

```json
{
  "mcpServers": {
    "adt-dev": {
      "command": "/absolute/path/to/node",
      "args": [
        "/absolute/path/to/mcp-abap-adt/bin/mcp-abap-adt.js",
        "--env-path=/absolute/path/to/env/dev.env",
        "--exposition=readonly,high"
      ],
      "env": {
        "NODE_TLS_REJECT_UNAUTHORIZED": "0",
        "NO_PROXY": "*",
        "no_proxy": "*"
      },
      "disabled": false
    }
  }
}
```

- `command` 写 node 的**绝对路径**更稳，避免客户端启动时找不到 node。
- 自签名证书场景需要 `NODE_TLS_REJECT_UNAUTHORIZED=0`；纯 HTTP 时无影响。
- WorkBuddy 改完配置必须**完全退出应用再打开**，并到连接器管理页点「信任」。

## 5. env 文件字段

模板见 `portable/env/dev.env.example`。只支持**整行注释**，不支持行内注释。

| 字段 | 说明 |
|---|---|
| `SAP_URL` | 含协议与端口 |
| `SAP_CLIENT` | 集团 |
| `SAP_LANGUAGE` | 登录语言；新建对象主语言随它，`ZH` 优先 |
| `SAP_SYSTEM_TYPE` | `onprem` |
| `SAP_CONNECTION_TYPE` | `http` |
| `SAP_AUTH_TYPE` | `basic` |
| `SAP_USERNAME` | **大小写须与 USR02 一致**（通常大写），否则创建对象报 `PAK049` |
| `SAP_PASSWORD` | 明文，文件权限 600 |
| `TLS_REJECT_UNAUTHORIZED` / `NODE_TLS_REJECT_UNAUTHORIZED` | 自签名证书设 `0` |
| `SAP_MASTER_SYSTEM` / `SAP_RESPONSIBLE` | 可选，部分系统创建/修改对象时需要 |

## 6. 自检

```bash
node verify.mjs --name=dev                                       # 不起 SAP 也能跑：server 启动 + 工具数量
node verify.mjs --name=dev --sql="SELECT mandt, mtext FROM t000"  # 端到端
```

| 现象 | 根因 | 处理 |
|---|---|---|
| `找不到 env 文件` | 没跑 `install.mjs`，或 `--name` 不一致 | 核对 `portable/env/<name>.env` |
| server 起不来 / 工具数不是 210 | Node < 22、依赖缺失、`--exposition` 同时写了 `high` 和 `low` | `node -v`；补 `node_modules`；去掉互斥参数 |
| `[OK] server 已启动` 但 SQL 失败 | 网络 / 凭据 / 集团 / 代理 | 按下方顺序排查 |
| `socket hang up` / `ECONNRESET` / CSRF 校验失败 | 请求走了本机代理 | 确认 `NO_PROXY=*` 与 `no_proxy=*`；脚本层用 `proxy: false` |
| 连上但全部查询为空 | 集团不对（空壳集团） | 换 `--client` 或 `SAP_CLIENT_OVERRIDE` |
| `PAK049` | 用户名大小写与 USR02 不一致 | 改大写 |
| 创建对象主语言不是中文 | `SAP_LANGUAGE` 未注入到 MCP 子进程 | 显式设 `SAP_LANGUAGE=ZH`（`call-adt-tool.js` 已处理） |
| Windows 解压报「文件名过长」 | 260 字符路径上限 | 解压到 `C:\tools\`，或用 7-Zip |
| 配置改了一直未连接 | 客户端没重启 / 没点信任 | 完全退出重开 + 点「信任」 |
| `requires the optional kerberos package` | 配了 `SAP_AUTH_TYPE=kerberos` | 改回 basic，或 `npm i kerberos` 补依赖 |

排查顺序固定：**ping ICM → 代理 → 证书 → 账号大小写 → 集团 → 权限**。

## 7. 卸载 / 换机

```bash
node install.mjs --uninstall --name=dev
```

迁移到新机器只需拷贝解压目录 + 重新跑 `install.mjs`（env 会重新生成）。**不要**把 `env/*.env` 打包发给别人。

## 8. 能力边界

- 只验证过 On-Premise + Basic Auth；ABAP Cloud / BTP 的 JWT、service key 走上游文档，本包未随包验证。
- 默认 `readonly,high` 暴露 210 个工具：读源码、查表（`GetSqlQuery`）、建/改/激活 ABAP 对象、查包内容、搜索对象等。完整清单见 `portable/TOOLS.md`。
- Kerberos SSO 的可选原生依赖已移除（体积/长路径）；`authType=basic` 不受影响。

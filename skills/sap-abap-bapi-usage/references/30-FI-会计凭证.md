# 30 · FI 会计凭证

> 分册归属：`sap-abap-bapi-usage`。覆盖过账、模拟、冲销、改已过账凭证、票据类行。
> 项目级封装接口的具体签名（`ZFM_FII001` / `ZFM_FII003` / `ZFM_FII001_SPLIT` 一类）见 `sap-abap-project-ops` §4。

## 1. 先确认有没有封装接口

优先级：**项目封装接口 > 裸 BAPI > BDC / POSTING_INTERFACE**。

项目上通常把「科目确定、金额校验、拆分、消息处理」都包在 `ZFM_FII*` 一类接口里，且**内部自己 `COMMIT`/`ROLLBACK`**。照抄老程序的裸 `BAPI_ACC_DOCUMENT_POST` 写法，常见后果是：
- 数据写重（外层又提交一次）；
- 或外层 `ROLLBACK` 以为能撤回，实际已提交。

拿不准时先看 FS / 项目总纲 §4，别猜。

## 2. 选型表

| 需求 | 走什么 | 要点 |
|---|---|---|
| 过账 | 封装接口优先；无封装才 `BAPI_ACC_DOCUMENT_POST` | 封装接口内部自己 `COMMIT`/`ROLLBACK`，调用方不要再提交/回滚 |
| 模拟导入 | `BAPI_ACC_DOCUMENT_CHECK`（与 POST 参数结构兼容，仅少 `obj_key` 出参） | 不 COMMIT 不 ROLLBACK；成功时凭证号留空 |
| 冲销 | 封装接口优先；历史写法 `BAPI_ACC_DOCUMENT_REV_POST`（需 `FI_REFERENCE_CREATE` 拼 `REVERSAL-OBJ_KEY_R`） | 冲销日期/原因在 `BAPIACREV`；判成败看 `MSGTY`，**不要用「MSGTX 非空 = 失败」**（成功时 MSGTX 也非空） |
| 改已过账凭证 | `FI_DOCUMENT_CHANGE`（组 `FACG`，`T_ACCHG` 只填 `FDNAME`+`NEWVAL`） | 抬头不传 `I_BUZEI`，行项目才传；**绝不直接 UPDATE `BSEG`** |
| 票据类行（`UMSKZ = W/X/Y`） | `POSTING_INTERFACE_*`（FB01 批输入） | `I_UPDATE` 值域实测只有 `S/A/L`，**没有「不更新数据库」档位** ⇒ 模拟模式下不要伪造成功，直接回 E |

## 3. 过账骨架（裸 BAPI 时）

```abap
" 1) 抬头
ls_doc_header-comp_code   = lv_bukrs.
ls_doc_header-doc_type    = 'SA'.
ls_doc_header-pstng_date  = lv_budat.   " 不是 POSTING_DATE
ls_doc_header-doc_date    = lv_bldat.
ls_doc_header-username    = sy-uname.

" 2) 行项目：借正贷负由 BSCHL 决定，金额一律传正数
"    SHKZG 由记账码反查 TBSL，不要手填
" 3) 金额字段直接传字符串，避免千分位
ls_item-amt_doc_cur = '1000.00'.

" 4) 双币必须每个 ITEMNO_ACC 两条 CURRENCYAMOUNT，且每种币种小计为 0
" 5) CURR_TYPE='10' 行也必须带 exch_rate（明细行 + 轧差行两处）
CALL FUNCTION 'BAPI_ACC_DOCUMENT_POST'
  EXPORTING documentheader = ls_doc_header
  IMPORTING obj_key        = lv_obj_key
  TABLES    accountgl      = lt_gl
            currencyamount = lt_cur
            return         = lt_ret.

READ TABLE lt_ret TRANSPORTING NO FIELDS WITH KEY type = 'E'.
IF sy-subrc <> 0.
  CALL FUNCTION 'BAPI_TRANSACTION_COMMIT' EXPORTING wait = 'X'.
ELSE.
  CALL FUNCTION 'BAPI_TRANSACTION_ROLLBACK'.
ENDIF.
```

## 4. FI 专属硬限制

- **`UMSKZ` 在三个 BAPI 结构里都没有字段** —— 票据类（W/S）走标准 BAPI 通道被静默丢弃、科目记错。只能经 `EXTENSION2` 增强落库，或整张走 `POSTING_INTERFACE_*`。
- **`BSEG-BUZEI` 是 `NUMC(3)`，单张 999 行物理上限**，BAPI 实际只吸纳 990 行 ⇒ 分片取 `989 明细 + 1 轧差`。边界必须覆盖 999 / 1000 / 1997（1997 按 `>999` 判会切出 1000 行而溢出）。
- **`BAPIACHE09` 没有 `EXCH_RATE` 字段** —— 双币（00+10 行）只给 00 行带汇率时，系统按 OB08 重定抬头汇率（填 7 落 8.28）。`CURR_TYPE='10'` 行也必须带 `exch_rate`。
- **双币凭证每个 `ITEMNO_ACC` 必须给两条 `CURRENCYAMOUNT`。** 缺 `10` 行报 `Inconsistent currency information`；拆分产生的轧差行同样要补。
- **`OBJ_KEY` 布局是 `凭证号(10)+公司代码(4)+会计年度(4)`**，年度在 **`+14(4)`**（常被误写 `+10(4)` 取到公司代码）。二次拆张时若只回一个凭证号 ⇒ 张数少报、按行回写指错凭证。
- **`BAPIACGL09-ITEM_TEXT` 只有 50 字符、`BAPIACHE09-HEADER_TXT` 只有 25 字符**，静默右截断。拼「前缀+后缀」先把前缀截到 `长度-后缀长度`。
- **`FI_DOCUMENT_CHANGE` 抬头不传 `I_BUZEI`**，只有行项目改才传；改已过账凭证**不走 UPDATE BSEG**。

## 5. 对账点

| 检查项 | 表 / 字段 |
|---|---|
| 凭证已生成 | `BKPF`：`BUKRS` + `BELNR` + `GJAHR` |
| 行数与金额 | `BSEG`：`COUNT(*)`、按 `SHKZG` 汇总借贷、合计为 0 |
| 票据类 | `BSEG-UMSKZ` 是否落上（不是空） |
| 双币 | `BSEG`：`CURR_TYPE` 出现 `00` 与 `10` 两套，`WRSL`/`HSL` 均非 0 |
| 分配/文本 | `BSEG-ZUONR`、`SGTXT` 逐字段比对 |
| 冲销 | 原凭证 `BKPF-STBLG` 指向冲销凭证；`BSEG` 反向 |

**先跑 `BAPI_ACC_DOCUMENT_CHECK` 或项目封装接口的模拟模式**：同样报错说明问题在科目/期间/字段状态组，不在你新写的代码。

# 判定 SAP 导出表的列映射（用数据对撞，不按标签猜）

## 何时加载

- 拿到一份自建 ABAP 报表导出的 Excel（通常是中文表头），要把它按 `工厂+物料`（或别的键）贴到对账表上。
- 导出表里有**语义近似**的列，肉眼分不清哪列对应源码里哪个字段。典型：`接收差额` vs `总入库金额`、`接收数量` vs `总入库数量`、`期初数量` vs `期末数量`。
- 结论会直接决定"两边是否有差额"，错了会得出几百万的虚假差异。

## 核心原则

**不要按列标签的语义相似度去猜。** 自建报表的导出列标签往往和源码注释 / 字段名不一致，甚至顺序都可能是程序里 `SORT` 出来的。唯一可靠的做法是**找一个只在唯一一组列上成立的恒等式，用真实数据逐位对撞**。

反向也成立：如果按标签猜出来的映射导致"大量行出现差异"，先怀疑映射错了，而不是先怀疑业务差异。

## 四步配方

### 第 1 步：从源码取权威定义（不靠猜）

在程序文本里定位 `SELECT` 列表 + `TYPES` 定义 + 算法注释，三者互证：

```abap
TYPES: BEGIN OF ty_ztco017,
         ...
         zje_ce  TYPE ztco017-zje_ce,   "接收差额
         zsl_ce  TYPE ztco017-zsl_ce,   "接收数量
       END OF ty_ztco017.

FORM frm_get_ztco017 TABLES it_mbew ... ot_ztco017 ...
  SELECT  ...
          SUM( ztco017~zje_ce ) AS zje_ce,   "接收差额
          SUM( ztco017~zsl_ce ) AS zsl_ce,   "接收数量
    FROM @lt_mbew AS mbew
         INNER JOIN ztco017 ON mbew~matnr = ztco017~matnr
                           AND ...
                           AND ztco017~bklas = @gc_bklas-val_5010   "评估类锁定
    GROUP BY ...
```

要点：
- 注释里的中文名（"接收差额"）**不一定**等于导出列标签。本例导出标签写的是"接收差额"确实对上了，但不能假设。
- 记下筛选条件（`bklas = 5010`、`jahrper = @iv_period`、`bwkey`）。对账时导出必须用**同样的筛选**，否则行数不一致。
- 找到消费该字段的公式（本例 `amt_zu = qty_zu * zje_ce / zsl_ce`），它就是构造比值恒等式的素材。

### 第 2 步：构造一个"只在唯一一组列上成立"的比值恒等式

从源码公式反推一个**可观测的比值**，然后用导出数据交叉验证。

本例：源码 `入库金额 = 入库数量 × ZJE_CE / ZSL_CE`，
→ 若映射正确，则 **`导出ZJE_CE列 ÷ 导出ZSL_CE列` 必须等于 `报表入库金额 ÷ 报表入库数量`**（对同一 `工厂+物料` 行）。

这一步的关键是**选一个能把候选列区分开的比值**。本例候选是两对：`(F,G)` 与 `(H,J)`。
- `F/G` = 接收差额/接收数量 = 单位价值
- `H/J` = 总入库金额/总入库数量 = 也接近单位价值 → **两个比值都能过**？

不行。要看量级：`接收差额` 是 ML 的**差异**，`总入库金额` 是**全额**，二者数量级差很多（本例 `ΣF = 269,762,133.56`，`ΣH` 明显更大）。所以比值恒等式要选**能放大差异**的那种，或直接比总量的量级。

### 第 3 步：多样本逐位对撞（相对误差 < 1e-6）

不要只验一行 —— 一行可能碰巧。取 5~10 个量级不同的样本，逐一算两侧比值：

```python
for matnr in samples:
    a = report_amt[matnr] / report_qty[matnr]      # 报表侧单位价
    b1 = exp[matnr]["F"] / exp[matnr]["G"]          # 候选 1
    b2 = exp[matnr]["H"] / exp[matnr]["J"]          # 候选 2
    assert abs(a - b1) / max(abs(a),1e-12) < 1e-6   # 只有候选 1 全过
```

判据：**全部样本只与唯一一组列逐位相等（相对误差 ≈ 0）**，其余候选至少有一个样本明显不等。

### 第 4 步：总量做二次确认

比值相等还可能是巧合（例如两个字段恰好成比例）。再用**合计**做独立确认：

```
导出 F 列合计 = 269,762,133.563363
报表 入库金额合计 = 269,762,133.563363   ← 逐位相同
导出 G 列合计 = 561,105
报表 入库数量合计 = 561,105
```

总量逐位相同，映射才算钉死。

### （可选）第 5 步：负例验证

确认"错误的那组列"确实会失败 —— 跑一次错误映射，看它是否复现出夸张的虚假差额（本例错误映射产出 `−1,313,108.85`、113 个物料"有差异"）。如果错误映射也能过，说明你的恒等式没有区分力，回第 2 步换一个。

## 真实踩坑案例：ZJE_CE 被错映射成"总入库金额"

**背景**：ZFIR007B 项目75（总账口径）= 269,960,412.57；ZCOR007N PROD 入库金额（ML 口径）= 269,762,133.56。

**错误过程**：把 `ZJE_CE/ZSL_CE` 映射到导出表的 `H 总入库金额 / J 总入库数量`（按标签语义猜），得出：
- 虚假差额 `−1,313,108.85`
- 113 个物料"有差异"

**纠正过程**：回查源码注释确认 `zje_ce`=接收差额、`zsl_ce`=接收数量；再用 5 个物料的单位价对撞：
- `报表 I÷H` 与 `F÷G` → 5/5 相对误差 = 0
- `报表 I÷H` 与 `H÷J` → 明显不等
- 二次确认：`ΣF = 269,762,133.563363` 与报表 `I652` 逐位相同

**纠正后结论**：650/650 行差额全为 0，**报表侧没有算错**。原猜测的"分摊失真/丢金额"全部作废。

**教训**：**"大面积出现差额"是映射错了的第一信号，不是业务差异的第一信号。**

## 附：口径桥（reconciliation bridge）的写法

判定列映射之外，两边口径不同时必须显式声明"对标哪个项目号"，否则残余差额没有意义。

本例：
```
W  = 进销存 PROD 入库金额合计         = 269,762,133.563363
75 = ZFIR007B 项目75（总账口径）      = 269,960,412.570000
W − 75 = −198,279.006637

# 换口径：75 = 66 − 67 − 70  →  66 − 67 = 75 + 70
66−67 = 270,080,518.09
W + 工厂间入库 K(270,641.202727) − 120,105.52(项目70) − (66−67) = −47,743.323910
```

要点：
- **两个口径的残余值不是同一个数**：对标 75 是 −198,279.01，对标 66−67 是 −47,743.32。写结论必须带上"对标 XXX"。
- 单列但不计入主列的口径项（本例"工厂间入库"）要在桥里显式加减。
- 残余占比写出来（本例 0.018%）帮助判断是不是"可忽略"。

## 附：openpyxl 读公式显示双等号 `==` 不是写坏了

`ws.cell(r,c).value` 读回 `'==Y2-I2'` 看着像坏了。实际 openpyxl 规范是 `<f>` 标签**内含**前导 `=`：

```xml
<c r="Z2" s="9"><f>=Y2-I2</f><v>0</v></c>   <!-- 正确 -->
```

读回时 openpyxl 会再补一个 `=`，属**显示现象**。校验方法：解压 xlsx 看 `xl/worksheets/sheet1.xml` 原始片段，而不是只看 openpyxl 的读回值。

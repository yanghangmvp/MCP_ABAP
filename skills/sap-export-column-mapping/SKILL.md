# 判定 SAP 导出表的列映射（用数据对撞，不按标签猜）

## 何时加载

- 拿到一份自建 ABAP 报表导出的 Excel（通常是中文表头），要把它按 `工厂+物料`（或别的键）贴到对账表上。
- 导出表里有**语义近似**的列，肉眼分不清哪列对应源码里哪个字段。典型：`接收差额` vs `总入库金额`、`接收数量` vs `总入库数量`、`期初数量` vs `期末数量`。
- 结论会直接决定"两边是否有差额"，错了会得出几百万的虚假差异。

## 核心原则

**不要按列标签的语义相似度去猜。** 自建报表的导出列标签往往和源码注释 / 字段名不一致，甚至顺序都可能是程序里 `SORT` 出来的。唯一可靠的做法是**找一个只在唯一一组列上成立的恒等式，用真实数据逐位对撞**。

反向也成立：如果按标签猜出来的映射导致"大量行出现差异"，先怀疑映射错了，而不是先怀疑业务差异。

## 四步配方

### 第 1 步：从源码取权威定义（不靠猜）

在程序文本里定位 `SELECT` 列表 + `TYPES` 定义 + 算法注释，三者互证：

```abap
TYPES: BEGIN OF ty_ztco017,
         ...
         zje_ce  TYPE ztco017-zje_ce,   "接收差额
         zsl_ce  TYPE ztco017-zsl_ce,   "接收数量
       END OF ty_ztco017.

FORM frm_get_ztco017 TABLES it_mbew ... ot_ztco017 ...
  SELECT  ...
          SUM( ztco017~zje_ce ) AS zje_ce,   "接收差额
          SUM( ztco017~zsl_ce ) AS zsl_ce,   "接收数量
    FROM @lt_mbew AS mbew
         INNER JOIN ztco017 ON mbew~matnr = ztco017~matnr
                           AND ...
                           AND ztco017~bklas = @gc_bklas-val_5010   "评估类锁定
    GROUP BY ...
```

要点：
- 注释里的中文名（"接收差额"）**不一定**等于导出列标签。本例导出标签写的是"接收差额"确实对上了，但不能假设。
- 记下筛选条件（`bklas = 5010`、`jahrper = @iv_period`、`bwkey`）。对账时导出必须用**同样的筛选**，否则行数不一致。
- 找到消费该字段的公式（本例 `amt_zu = qty_zu * zje_ce / zsl_ce`），它就是构造比值恒等式的素材。

### 第 2 步：构造一个"只在唯一一组列上成立"的比值恒等式

从源码公式反推一个**可观测的比值**，然后用导出数据交叉验证。

本例：源码 `入库金额 = 入库数量 × ZJE_CE / ZSL_CE`，
→ 若映射正确，则 **`导出ZJE_CE列 ÷ 导出ZSL_CE列` 必须等于 `报表入库金额 ÷ 报表入库数量`**（对同一 `工厂+物料` 行）。

这一步的关键是**选一个能把候选列区分开的比值**。本例候选是两对：`(F,G)` 与 `(H,J)`。
- `F/G` = 接收差额/接收数量 = 单位价值
- `H/J` = 总入库金额/总入库数量 = 也接近单位价值 → **两个比值都能过**？

不行。要看量级：`接收差额` 是 ML 的**差异**，`总入库金额` 是**全额**，二者数量级差很多（本例 `ΣF = 269,762,133.56`，`ΣH` 明显更大）。所以比值恒等式要选**能放大差异**的那种，或直接比总量的量级。

### 第 3 步：多样本逐位对撞（相对误差 < 1e-6）

不要只验一行 —— 一行可能碰巧。取 5~10 个量级不同的样本，逐一算两侧比值：

```python
for matnr in samples:
    a = report_amt[matnr] / report_qty[matnr]      # 报表侧单位价
    b1 = exp[matnr]["F"] / exp[matnr]["G"]          # 候选 1
    b2 = exp[matnr]["H"] / exp[matnr]["J"]          # 候选 2
    assert abs(a - b1) / max(abs(a),1e-12) < 1e-6   # 只有候选 1 全过
```

判据：**全部样本只与唯一一组列逐位相等（相对误差 ≈ 0）**，其余候选至少有一个样本明显不等。

### 第 4 步：总量做二次确认

比值相等还可能是巧合（例如两个字段恰好成比例）。再用**合计**做独立确认：

```
导出 F 列合计 = 269,762,133.563363
报表 入库金额合计 = 269,762,133.563363   ← 逐位相同
导出 G 列合计 = 561,105
报表 入库数量合计 = 561,105
```

总量逐位相同，映射才算钉死。

### （可选）第 5 步：负例验证

确认"错误的那组列"确实会失败 —— 跑一次错误映射，看它是否复现出夸张的虚假差额（本例错误映射产出 `−1,313,108.85`、113 个物料"有差异"）。如果错误映射也能过，说明你的恒等式没有区分力，回第 2 步换一个。

## 真实踩坑案例：ZJE_CE 被错映射成"总入库金额"

**背景**：ZFIR007B 项目75（总账口径）= 269,960,412.57；ZCOR007N PROD 入库金额（ML 口径）= 269,762,133.56。

**错误过程**：把 `ZJE_CE/ZSL_CE` 映射到导出表的 `H 总入库金额 / J 总入库数量`（按标签语义猜），得出：
- 虚假差额 `−1,313,108.85`
- 113 个物料"有差异"

**纠正过程**：回查源码注释确认 `zje_ce`=接收差额、`zsl_ce`=接收数量；再用 5 个物料的单位价对撞：
- `报表 I÷H` 与 `F÷G` → 5/5 相对误差 = 0
- `报表 I÷H` 与 `H÷J` → 明显不等
- 二次确认：`ΣF = 269,762,133.563363` 与报表 `I652` 逐位相同

**纠正后结论**：650/650 行差额全为 0，**报表侧没有算错**。原猜测的"分摊失真/丢金额"全部作废。

**教训**：**"大面积出现差额"是映射错了的第一信号，不是业务差异的第一信号。**

## 附：口径桥（reconciliation bridge）的写法

判定列映射之外，两边口径不同时必须显式声明"对标哪个项目号"，否则残余差额没有意义。

本例：
```
W  = 进销存 PROD 入库金额合计         = 269,762,133.563363
75 = ZFIR007B 项目75（总账口径）      = 269,960,412.570000
W − 75 = −198,279.006637

# 换口径：75 = 66 − 67 − 70  →  66 − 67 = 75 + 70
66−67 = 270,080,518.09
W + 工厂间入库 K(270,641.202727) − 120,105.52(项目70) − (66−67) = −47,743.323910
```

要点：
- **两个口径的残余值不是同一个数**：对标 75 是 −198,279.01，对标 66−67 是 −47,743.32。写结论必须带上"对标 XXX"。
- 单列但不计入主列的口径项（本例"工厂间入库"）要在桥里显式加减。
- 残余占比写出来（本例 0.018%）帮助判断是不是"可忽略"。

## 附：openpyxl 读公式显示双等号 `==` 不是写坏了

`ws.cell(r,c).value` 读回 `'==Y2-I2'` 看着像坏了。实际 openpyxl 规范是 `<f>` 标签**内含**前导 `=`：

```xml
<c r="Z2" s="9"><f>=Y2-I2</f><v>0</v></c>   <!-- 正确 -->
```

读回时 openpyxl 会再补一个 `=`，属**显示现象**。校验方法：解压 xlsx 看 `xl/worksheets/sheet1.xml` 原始片段，而不是只看 openpyxl 的读回值。

## 实战二：从 FAGLFLEXT 原始导出复现自建总账报表

场景：财务/业务导出整张 `FAGLFLEXT`（新总账**总计表**，40k 行 × 122 列），要复现某个自建总账报表（如 ZFIR007B MS 报表）的口径，或反查报表数字出处。

### 1. 过滤条件从源码抄，不要自创

ZFIR007B 的 `START-OF-SELECTION`：

```abap
SELECT ryear drcrk rpmax rtcur racct rbukrs rfarea
       hslvt hsl01 ... hsl16
  INTO CORRESPONDING FIELDS OF TABLE it_itab
  FROM faglflext
  WHERE ryear  = p_year     " 2026
     AND rldnr  = p_rldnr   " '0L'
     AND rrcty  = '0'
     AND rbukrs = p_bukrs   " 'LNT'
     AND prctr IN s_prctr.  " 通常为空 = 不限
```

导出后先 `Counter` 一遍 `RYEAR/RLDNR/RRCTY/RVERS/RBUKRS`，确认导出没夹带别的期间或分类账。

### 2. 列定位：中文表头是**重复**的，只能按序号

FAGLFLEXT 的表头有 16 个一模一样的「本位币中的业务总计」，按名字找必然错位。**必须按 0 基序号定位**：

| 序号 | 字段 |
|---|---|
| 0 | RYEAR |
| 1–9 | OBJNR00–OBJNR08（9 个对象编号，常全 0） |
| 10 / 11 | DRCRK 借贷标识 / RPMAX 期间 |
| 21 / 23 | RACCT 科目 / RBUKRS 公司代码 |
| 16 / 17 / 18 / 19 | RPROC 参考过程 / RLDNR / RRCTY / RVERS |
| 36 | TSLVT |
| 37–52 | TSL01–TSL16 |
| **53** | **HSLVT 年初结转** |
| **54–69** | **HSL01–HSL16 本位币各期发生额 ← 自建报表通常用这组** |
| 70–86 / 87–103 / 104–120 | KSL / OSL / MSL 组 |
| 121 | TIMESTAMP |

Excel 列号 = 序号 + 1。所以 **HSL09 在 0 基索引 62 / Excel 第 63 列**。

### 3. 符号规则

- **HSL 本身已带借贷符号**（借方正、贷方负），**不要再按 DRCRK 翻转**。DRCRK 只表示该记录的净方向，不参与金额符号。
- 配置表（如 ZTFI003B）里项目级的**「贷方标记」= 'X'** 时，取数结果整体乘 −1：

```abap
IF conf-zfisign = 'X'.
  <fs1> = <fs1> - <fs>.     " 即累加后取反
ELSE.
  ADD <fs> TO <fs1>.
ENDIF.
```

实测：项目70（贷方标记 X，科目 0078010300-0078010999）原始合计 `−120,105.52` → 取反 `+120,105.52`，与报表一致。

### 4. 校准：拿报表的已知项目值来对撞（同「四步配方」）

用导出数据按 `RACCT` 区间求和，去碰报表上已知的项目金额；**逐位相等才算列定位正确**：

```
项目2 科目 0071010101-0071010111  HSL09 求和 = 259,136,630.70  vs 报表 259,136,630.70 ✔
项目16 科目 0072 段                HSL09 求和 =   5,270,029.17  vs 报表   5,270,029.17 ✔
项目25 科目 0073 段                HSL09 求和 =   6,534,954.56  vs 报表   6,534,954.56 ✔
项目70 科目 0078010300-0078010999  HSL09 求和 =    −120,105.52 取反 = +120,105.52 ✔
```

再加一条**年度累计**的独立确认：`Σ(HSL01..HSL09) = 2,215,148,560.93` = 报表「年度累计发生额」逐位相同。

一次校准 4/4 全中，说明列偏移 + 符号规则都对；有一处不对，优先怀疑列偏移。

### 5. 已知边界

- **FAGLFLEXT 是汇总表，不含科目名称、不含行项目**。要科目描述得导 `SKAT`/`SKA1`；要凭证明细得上 `ACDOCA` 或 `FAGLL03H`。
- `RACCT` 在 Excel 里会掉前导零（`0071010101` → `71010101`），比较前必须 `str(int(v)).zfill(10)`。
- 同一段里常有多个「镜像」科目对（如 `0071010101` ↔ `0012130309`，`0045010101` ↔ `0012010309`，`0078010101/0078010501` ↔ 项目63），数值逐月相等、符号相反；不要把它们当成两笔业务。
- 靠「逐笔找某个差额值」很可能找不到：本例 198,279.01 既不是任何 `(科目 × 期间)` 的发生额，也不是任何两科目之差（穷举 304 科目 × 两两 = 4.6 万组全落空）。**这时不要停在「无法隔离」上——先做下面的「实战三」把差异定位到某一侧，再索要对应的凭证明细。**

## 实战三：复现失败时，用「会计恒等式」把差异定位到某一侧

场景：报表某一列（如项目75 TOTAL COST OF GOODS MANUFACTURED）与另一个信息源（进销存报表）差一个不大不小的数，
逐笔找差额值穷举全落空。**此时换思路：不去找「差额本身」，而是去找「差额在哪个等式项里漏掉」。**

### 步骤 1：先把报表公式复现到逐月逐位（复现不了就别谈定位）

自建报表的项目大多是「科目区间求和 + 符号取反」的加减树，从配置表（ZTFI003B 这类）抄下来即可。
**但要注意两类隐藏口径：**

1. **同区间同符号的两个项目，可能因「名称关键词」走不同后处理。**
   实测 ZFIR007B 源码：

   ```abap
   LOOP AT it_output WHERE text CP '*BEGINNING*'.   " 项目64 V.BEGINNING WORK IN PROGRESS
     it_output-hsl02 = ls_output-ncs + ls_output-hsl01.
     it_output-hsl03 = ls_output-ncs + ls_output-hsl01 + ls_output-hsl02.   " 期初 + Σ 前(m-1) 月
   ENDLOOP.
   LOOP AT it_output WHERE text CP '*ENDING*'.      " 项目67 VII.ENDING WORK IN PROGRESS
     it_output-zhsl01 = it_output-hsl01 = ls_output-ncs + ls_output-hsl01.
     it_output-zhsl02 = it_output-hsl02 = ls_output-ncs + ls_output-hsl01 + ls_output-hsl02.  " 期初 + Σ 前 m 月
   ENDLOOP.
   ```

   配置表里 64 和 67 的科目区间、贷方标记**完全一样**。若把它们当作同一个东西，会双双抵消，
   算出来的数「看起来合理但差一个数」（本例差 861,096.34 = 当月 WIP 净增加额）。
   **正确结论：`两者相减 = 该科目区间的当月发生额`**，于是报表公式塌缩成
   `项目75 = 项目63 − ΔWIP净(当月发生) − 项目70`。

   > 通用规则：报表项目名里出现 BEGINNING / ENDING 且指向同一科目区间时，多半是「上月末 vs 本月末」，
   > 相减即当月发生额。**复现时先假设相减，去撞报表值；撞上了就是它。**

2. **校验必须逐月全量对撞，不能只看一个月。**
   本例用单月（9 月）对撞时，错误口径也「像那么回事」；12 个月一起撞，只有 9 月对不上，立刻暴露。

### 步骤 2：写会计恒等式，把差额变成「缺口」

```
本期投入(项目63) = 产成品入库 + ΔWIP净 + 转出其他(项目70) + 缺口
9月: 270,941,614.43 = 269,762,133.50 + 861,096.34 + 120,105.52 + 198,279.07
```

**缺口 = 报表值 − 另一信息源值**，且自动等于「四个流向没把投入吃完的部分」。
这一步的价值：把一个「找不到出处的数」翻译成一个**有会计含义的命题**——
「本期投入里有 19.8 万没落到产成品/WIP/转出任何一侧」。

### 步骤 3：用两个独立来源判定「哪一侧是事实」

不要假设任何一侧对。找**第二条独立数据链**去证同一件事：

- 总账汇总（FAGLFLEXT）科目 `0012010301` 9月 = 269,762,133.50
- 物料分类账侧（ZTCO017 评估类 5010）+ 进销存报表 PROD 入库 = 269,762,133.563363

两者差 0.06（按行分位取整）→ **产出侧双证，是事实；缺口在投入侧**。

### 步骤 4：逐月缺口序列做「量级判别」

```
1: +10,446.13   2: +0.46   3: -6,079.82   4: +0.02   5: -76.81
6: +120.21      7: -0.08   8: +20.72      9: +198,279.07   10: 0.00
```

- 若**多数月逐位相等、只有一个月跳** → 不是长期结构性口径差（可以据此**推翻**业务方给的归因）。
- 若**每月都差一点点** → 是分位取整/挂账时点差，不是业务差异。
- 本例 2/4/7/8/10 月逐位相等，9 月跳两个数量级 → 单月一次性问题。

### 步骤 5：到汇总行的「结构性特征」里找抓手

FAGLFLEXT 虽然没有凭证号，但每行的 `DRCRK / RPMAX / RPROC / 金额` 是有的。可用的特征：

- **`RPROC` = 凭证来源**：`BKPFF`=财务凭证、`MLHD`=物料分类账、`MKPF`=物料凭证、`AUAK`=CO结算、`BKPF`、`AMDP`…
  同科目内 `BKPFF 贷方` 与 `MLHD 借方` **成对同额**，是「月末冲销暂估 + ML 重估」的标准模式。
- **笔数与最大单笔的月度对比**：本例 0071 段 BKPFF 冲销笔数 9月=13（8月=11、7月=12），最大单笔 552,406.49（8月 487,067.99）。
- **段级恒等式交叉验证**：发现 `0078 全段 = −项目63`（精确到分），且 `0078 0100-0299 = −(63−70)`、`0078 0500-0599 = −项目70`。
  这类**镜像关系**是强校验：它证明报表口径在总账里确实有对应的转账结构。
- **跨月挂账配对**：本例每对「本月挂账 X / 下月冲回 −X」都能在相邻期间找到同额反号行
  （如 9月 `0012010301 借 +3,348,736.92` ↔ 10月同额贷方）。找不到配对的「孤儿笔」是嫌疑点。

### 步骤 6：收口——交付「定位 + 索要凭证明细」

到这一步已经能给出：**差异在投入侧、金额、月份、可疑科目、可疑笔数**。
最后一步只能要凭证明细（`ACDOCA` / `FAGLL03H`），并明确指定**科目 + 月份 + 看借贷哪一方**。

### 结论留痕（重要）

业务方给的归因（本例「委外采购加工费」）**必须被独立验证，不能直接采信**。
本例推翻它的硬证据：委外专用科目 `0071010113`、`0073890000-0073899999` **全年零发生额**，
且「只有 9 月才差」与「常年发生的委外业务」在逻辑上不相容。
交付物里保留「结论变化史」，写清楚哪一版作废、被什么证据推翻——比只给最终结论更有价值。

## 实战四：用 ACDOCA 行项目核对 FAGLFLEXT 总计表，抓「口径断裂」

场景：报表口径已经 100% 复现，但和另一个信息源差一个数，且汇总层穷举不到。
**下一步必然是拿行项目。** 用户导出的行项目常见形态是 **GBK 编码的 Tab 分隔文本，扩展名却是 `.XLS`**。

### 1. 解析（别被扩展名骗了）

```bash
file 123.XLS     # → ISO-8859 text, with CRLF line terminators   ← 不是真 XLS
```

```python
raw = open('123.XLS','rb').read().decode('gbk', errors='replace')
recs = [l.split('\t') for l in raw.split('\r\n')[1:] if l.strip()]
```

`openpyxl` / `xlrd` / `pandas.read_excel` 全部读不了。**先 `file` 探一下，再决定解析器。**

### 2. 关键列（SAP 行项目导出 31 列的 0 基序号）

| 序号 | 字段 | 用途 |
|---|---|---|
| 3 / 4 | BLART 凭证类型 / **BELNR 凭证号** | 定位到具体凭证 |
| 5 / 6 | HKONT 总账科目 / 科目短文本 | 确认科目名 |
| 7 | SHKZG 借贷（S/H） | **注意：S 也可能是负数**（借方红字） |
| 8 / 9 | KOSTL 成本中心 / 文本 | `99999 公共` = 结转类 |
| 11 / 14 | CURRVAL_0D 凭证货币 / **CURRVAL_10 公司代码货币** | 通常取 14 |
| **15 / 16** | **BKTXT 凭证抬头 / SGTXT 文本** | **业务性质，最关键的线索** |
| 18 | BUDAT 过账日期 | 时点 |
| 26 / 28 | TCODE / USNAM | 哪个程序、谁做的 |
| **29** | **GKONT 抵销科目** | **对方科目，用于还原完整分录** |

### 3. 核对姿势：借贷分列对比，定位断裂在哪一侧

**别只比净额。** 把总计表和行项目分别按「正值合计 / 负值合计」列出：

```
                    借方(S)              贷方(H)            净额
ACDOCA 明细   261,177,269.09      -2,137,282.44     259,039,986.65
FAGLFLEXT     261,177,269.09      -2,040,638.39     259,136,630.70
差 异                   0.00         -96,644.05         -96,644.05
```

**借方两侧完全一致、差异全在贷方** → 立刻知道是「某笔贷方/红字凭证没进总计表」，
而不是「口径整体偏移」。再去行项目里找那笔金额 = 96744.05 的凭证，一击即中。

> 陷阱：SAP 的 **SHKZG='S' 但金额为负** 的行（借方红字），按净额汇总时会"看起来"在借方，
> 实际等效于贷方。**必须先按金额正负分组，再和总计表比。**

### 4. 用 BKTXT 找业务性质

本例一次性命中：`BKTXT = '委托加工MPC调整'`。**凭证抬头是最有信息量的字段**，
比参考过程（BKPFF/MLHD）更能说明"这笔到底是干什么的"。

按 BKTXT / SGTXT 分组汇总，通常能立刻看出：
- 主业务（大额、单笔）
- 调整/冲销（成对正负、净 0）
- 分摊（成对红冲、净 0）
- 纯数量行（金额 0，如货物移动 WA 类型）

### 5. 全局反向搜索：拿差额去 FAGLFLEXT 里搜

行项目给的差额（如 96,644.05）**回到 FAGLFLEXT 全表搜**——如果只在某个陌生科目上命中一次，
那个科目往往就是答案的另一条腿（本例命中 `0012130701` 原材料库存，且**上个月也有一笔近似金额**，
说明是新业务，可据此判断"什么时候开始出问题"）。

> 搜「某科目某月一笔、上月一笔近似金额」是判断**新业务引入时点**的好办法。

### 6. 结论必须区分「已解释」和「未解释」

本例：找到 96,644.05，但差额是 198,279.01 —— **只解释 48.7%**。
**绝不能写成"找到原因了"。** 正确写法：

- 已定位：96,644.05（凭证 3200152844 / 3200152860，总计表少了后者）
- 修正后剩余：101,634.96，仍未定位，落在 0072/0073/WIP/0078 段之一
- 下一步：要凭证 3200152844/3200152860 的**完整分录（所有科目）** + 剩余段的明细

### 7. 拿到凭证完整分录后：做「收录情况」四象限对比

行项目只给你**一个科目**的腿。要判定"是整张凭证没进总计表，还是只有一条腿没进"，
需要让对方补**该凭证的完整分录（所有科目）**，然后逐个科目对比：

| 科目 | ACDOCA 明细 | FAGLFLEXT | 差 | 说明 |
|---|---|---|---|---|
| 71010101 原材料成本 | 两张 +/− 各一 | 含 +96,644.05 一笔 | -96,644.05 | 总计表只收了一张 |
| 78010101 生产成本归集 | 两张对冲，净 0 | 含 -96,644.05 一笔 | +96,644.05 | 同上 |
| 12130701 委托加工生产 | 两张对冲，净 0 | 仅 +96,644.05 一笔 | -96,644.05 | 同上 |
| 12130309 原材料账户结转 | 两张对冲，净 0 | 含 -96,644.05 一笔 | +96,644.05 | 镜像成立 |

**四个科目同向差同额 → 整张凭证（4 条腿）都没进总计表**，而不是某条腿的问题。结论要写清楚。

### 8. 镜像科目 = 免费的完整性校验（强烈推荐）

自建报表体系里常有**镜像科目对**（数值逐月严格相等、符号相反）。本例：

```
FAGLFLEXT 9月:  0071010101 = +259,136,630.70
                0012130309 = -259,136,630.70   ← 严格镜像
FAGLFLEXT 9月:  0071010101 = +259,136,630.70   （含 +96,644.05）
                ACDOCA      = +259,039,986.65   （含 +96,644.05 和 -96,644.05）
```

**用法**：先验证镜像在两套口径下是否都成立。若某月镜像被破坏，就是"某一条腿漏收"的铁证。
本例另一个例子：`0012130701` 在 FAGLFLEXT 里**只有 +96,644.05、没有对应的冲销**，
而行项目里明明有两笔对冲 —— 一眼就能看出总计表漏收。

> 实战价值：**搜一个可疑金额，命中唯一科目后，去看该科目有没有「该出现的反方向金额缺席」**。
> 缺席 = 漏收。

### 9. 结论必须沿用「已解释 / 未解释」两段式

拿完全部分录后的最终写法：

- **已定位**：96,644.05（整张 3200152860 未进总计表，4 条腿全缺）→ 0071 段虚增 → 项目75 虚增同额
- **修正后**：项目75 = 269,960,412.57 − 96,644.05 = 269,863,768.52
- **仍未定位**：101,634.96（FAGLFLEXT 全表扫 101,634.96 / 4,990.91 / 5,026.48 / 193,252.53 均 0 命中）
  → 必落在 0072/0073/WIP/0078 段，需那些段的行项目

**不要为了"结案"把 96,644.05 说成全部原因（它只占 48.7%）。**

### 10. 拿到新段明细后：先做「干净段排除法」，再用恒等式代数改写收缩残差

**目标**：一个缺口定位到某一段后，下一步是**排除**，而不是"再列一个可能原因"。

**第一步：严格对撞（比总额多两层）**

不要只看"总额对不对"。三层都过才算干净：

1. **总额**：明细合计 vs FAGLFLEXT 合计
2. **借贷分列**：明细 S/H 合计 vs FAGLFLEXT 按 DRCRK 分列的 S/H 合计
3. **逐科目**：每个科目的明细合计 vs FAGLFLEXT 该科目合计

> 案例：0072/0073 段三层全 0.00（借 34,717,038.37 / 贷 -22,912,054.64）→ **彻底排除，不用再看**。

**第二步：口径先选对，再谈差异**

同一份明细常有多列金额（凭证货币 `CURRVAL_0D` vs 公司代码货币 `CURRVAL_10`）。
**必须用与目标表同本位币的那一列**（FAGLFLEXT 的 HSL ↔ `CURRVAL_10`）。

> 案例：0072 段两种口径都对，0073 段**只有** `CURRVAL_10` 对（`CURRVAL_0D` 差 -66,365.85，是外币折算）。**口径选错会误判成"差异"。**

**第三步：把报表公式改写成"更少科目"的等价式**

原式项多（项目63 = 三段之和），不利于定位。找一条**科目更少**的代数等价式：

> 案例：`项目75 = |78010101 生产成本转出| − 0012110301(WIP)`
> 只涉及 2 个科目，一眼看出 269,960,412.57 = 270,821,508.91 − 861,096.34。

**第四步：把缺口写成"两侧科目之差"，缩小候选**

> 案例：`|78010101| − 0012010301(产成品入库) − 0012110301(WIP) = 198,279.07`
> 含义："生产成本转出的钱，比产成品入库 + WIP 多 X"。
> 再用双证排除某一侧（0012010301 已被总账 + 进销存双证）→ 候选只剩 2–3 个科目。

**第五步：交付"下一份要导的明细"**

不要笼统说"再查查看"。给出**具体科目 + 具体分组维度**：

> "导 `78010101` 的 9 月明细，按 `GKONT`（抵销科目）分组 → 看 X 转去了哪里。"

这样每轮都收敛，不会原地打转。

### 11. 判定"某科目有无额外漏收"：看借方是否精确 + 手工调整凭证

**判据（快）**：把 ACDOCA 明细与 FAGLFLEXT 做借贷分列对比。

- 若**借方完全相等、差异全在贷方且恰等于某个已知金额** → 该科目只有那一笔漏收，**无额外漏收**。

> 案例：78010101 借方两侧都 516,187.86；贷方差恰 +96,644.05，与 71010101 侧的 -96,644.05 **互为镜像** → 同一张凭证两条腿，双重证实，无额外漏收。

**残余缺口的头号嫌疑：`BKTXT` 非空的"手工调整凭证"**

标准业务（结转 ZCOR012、结算 CO88）之外，`BKTXT` 非空的行往往是月末手工调整：

- `重分类调整凭证`（新增走 ZCOR001，冲销走 FB08）
- `FLT.Cost Misc. Transfer`
- `结算费用尾差调整`

**做法**：把 `BKTXT` 非空的行单独列出，算净额，看是否落在"缺口"量级。

> 案例：9 月手工调整净 +115,022.69，与残余缺口 101,634.96 同量级 → 嫌疑最大。

**兜底判据**：若全局扫描（单科目、两科目加减）对缺口值 **0 命中**，说明缺口是**多凭证复合效应**，不是某个科目余额 —— 此时只能拿到"对方科目"明细才能拆。

### 12. 用「入账凭据分组」反推科目真实构成，并与第三方系统闭环

**手法**：拿到某科目的行项目明细后，**按 `BKTXT`（凭证抬头）分组**，往往一眼看出该科目当月由哪几类业务构成。

> 案例：产成品 `0012010301` 的 BKTXT 分组只有两类：
> - `2026.09库存科目还原` 269,302,637.21（1 行，凭证 3200152842）
> - `重分类调整凭证` 净 459,496.29（13 行：FB08 冲销 +3,808,233.21 / ZCOR001 -3,348,736.92）
> → 净额 269,762,133.50 = 269,302,637.21 + 459,496.29。

**再与第三方报表闭环**：若另一个系统（进销存 ZCOR007N / 物料分类账 ZTCO017）也报同一个数，就用上面的分解去对：

> 案例：ZTCO017 的「总入库金额」269,302,637.21 = 库存科目还原；「接收差额」269,762,133.56 = 产成品净额；两者之差 459,496.35 = 重分类调整。
> **→ 修正了此前"差额是材料价格差异"的误判。** 差额的真相必须到对方系统里找对应的手工调整凭证，**不能按名字猜**（正呼应本文「不要按标签猜」的核心原则）。

**要点**：`BKTXT` 非空的行 = 手工 / 调整业务，是解释口径差的第一手材料；把它们单独列出来看净额，比推测快得多。

### 13. 全段排除后的收口：区分「漏收型」与「口径型」差异

**当所有相关段都通过三层对撞（差 0.00）后，不要再找"下一笔错"。** 结论应改写为：

> 差异 = ① 已定位的漏收（若有）+ ② 口径型楔子（非账证错误）

**判据**：

- 三层对撞**有差** → **漏收型**（账上确实少记 / 多记）→ 继续追凭证
- 三层对撞**全 0 但报表仍不吻合** → **口径型**（两套报表定义不同）→ 找月末调整凭证 + 请业务确认口径

**口径型差异的定位手法**：把两侧的**月末手工调整凭证**（`BKTXT` 非空）列出来对齐。

> 案例：产成品侧 9 月有「库存科目还原」（3200152842）、「重分类调整」；生产成本侧有「FLT.Cost Misc. Transfer」「重分类调整」「结算费用尾差」。这些调整在科目间"搬运"金额，是口径差的来源。
> **验证搬运是否中性**：把调整在各科目间的净额相加，应 ≈ 0（案例：78010101 +25,971.28 / 产成品 +459,496.29 / WIP -485,467.57 = 0）。

**交付话术**：明确告诉用户"**这不是账记错了，是两个报表口径不同**"，并给出定量桥，避免无止境倒查。

> 案例终局：`项目75 269,960,412.57 − 进销存 269,762,133.56 = 198,279.01`，而
> `198,279.01 = 96,644.05（汇总表↔行项目不一致）+ 101,634.96（口径型）`——**两个分量性质不同，必须分开表述**，别把 198,279.01 整包说成"漏账"。

### 14. 凭证腿平衡检测：用「已见腿之和」找未见腿，并甄别残差真伪

**做法**：拿到某科目（或若干科目）的行项目明细后，按 `BELNR` 分组，把该凭证在**本文件里能看到的所有腿**相加。凭证必然借贷平衡，所以：

- 和 = 0 → 该凭证在本文件中的腿齐全（**注意：不能反推"凭证只有这几腿"**，见下方陷阱）
- 和 ≠ 0 → **有腿不在本文件里**（科目未导出），差额 = 未见腿净额

```python
from collections import defaultdict
g = defaultdict(float)
for r in rows:                 # rows = 某科目行项目明细
    g[r[4]] += float(r[14])    # col4=BELNR, col14=CURRVAL_10
for belnr, s in g.items():
    if abs(s) > 0.005:
        print(belnr, s)        # s = 未见腿净额（残差）
```

**陷阱**：和 = 0 **不等于**"凭证只有这些腿"。案例里 `3200152860` 在已导出的两个科目上恰好一正一负抵平（和 0），但它作为 `3200152844` 的镜像凭证，结构应当同构（4 腿）——另两腿落在未导出科目上。**判断凭证真实腿数，看它的镜像凭证。**

**用残差反查：必须做单行搜索甄别，别把算术量当漏账。**
把未见腿净额拿到「全部已导出明细 + 总计表」里做**单行搜索**：

- 命中 → 该笔真实存在，只是对应科目没导
- **0 命中 → 它只是"已见腿之和"这个算术量，不是任何一条真实分录** → 未见腿分散在多个科目，或该凭证的腿结构与你设想的不同；**必须去取完整凭证（按 `BELNR` 查 FB03 / ACDOCA），而不能继续按科目导**

> 案例：`450,461.51` / `271,442.60` / `536,867.47` 在全部已导出明细与总计表中 **0 命中** → 不可再当成"一笔漏账"去追，只能索要完整凭证。

### 15. 「总计表 vs 行项目」不一致：先排除分类账，再定性

**症状**：同一科目、同一期间的合计，`FAGLFLEXT`（总计表）与行项目明细对不上，且差额成对镜像。

**第一步永远是查 `RLDNR`**（行项目 0 基 `col1`）。若明细里混入了非取数分类账的行，而总计表口径是 `rldnr='0L'`，那"差额"只是**口径混样**，不是漏账。**必须全为 `0L` 才继续下结论。**

```python
from collections import defaultdict
d = defaultdict(lambda: [0, 0.0])
for r in rows:                       # col1=RLDNR, col14=金额
    d[r[1]][0] += 1; d[r[1]][1] += float(r[14])
# 期望：只有一个键 '0L'
```

**第二步：确认总计表本身是聚合表，不是凭证明细表。** `FAGLFLEXT` 的「对象编号」列（0 基 `1–9`）实测**全为 `0`**——它不含凭证号，行粒度 = 分类账 × 公司代码 × 科目 × 期间 × 借贷标识。因此：

- 表述上不能说"某张凭证没进总计表"，只能说"**总计表在某科目某方向上少了 X**"
- 对撞时必须先按 **科目 × 借贷方向** 聚合再比；行项目里同科目同方向的多行，在总计表里会被合并成一行，逐行比会误判

**第三步：镜像差额的成因表述。** 若 A / B 两科目出现 ±X 的严格反向差，且 X 对应某张红字冲销凭证（同额反向、同抬头、同日），正确表述是：

> 总计表未体现该红字凭证的冲销，导致 A 科目借方虚增 X、B 科目贷方虚增 X。

这属 **「汇总表与行项目不一致」**（汇总未刷新 / 反向凭证处理差异），需 SAP 侧核查（`FAGL_FCV` 重建汇总；FB03 查凭证过账与冲销状态），**不是业务做账错误**。

**第四步：用镜像科目对做旁证。** 若已知 `A ↔ A'` 为镜像科目对（严格 ± 相等），A 上出现 X 的差，则 A' 上应有 -X 的痕迹。

> 案例：`0012130309` 净 -259,136,630.70 ＝ `71010101` 净 +259,136,630.70 的相反数。

### 16. 「总计表 vs 行项目」差额的**端到端双层验证**（同一笔差异必须两处同额出现）

只在一侧发现 X 的差就下结论，容易冤枉。**同一笔红字/冲销凭证，应在「被冲销科目」与「对手科目」两侧各差 ±X，且都等于该凭证金额。** 做法：

```
对每个候选科目 A，同时算：
  A(FAGLFLEXT 汇总)  vs  A(行项目明细导出)  →  差 dA
若 dA == 某凭证金额 X，再到其对手科目 B 上验证 dB == ∓X。
两处都命中 → 结论成立（汇总表未落该凭证）。
```

实测案例（某客户 LNT 2026-09）：`71010101` 汇总 259,136,630.70 − 明细(`123.XLS`) 259,039,986.65 = **96,644.05**；`78010101` 汇总 −270,821,508.91 − 明细(`78010101.XLS`) −270,724,864.86 = **96,644.05**，方向相反。两处都等于委托加工 MPC 调整凭证 3200152844 的金额 → 强行坐实「3200152860 红字腿未进汇总表」。

**★ 关键前提：明细导出必须"两腿都在"。** 判据是看明细里该抬头/凭证的**净额为 0**（如 `Y4 委托加工MPC调整 2 行 0.00`）。若明细只有一条腿，那差额是明细不完整，不是汇总表问题——结论完全相反。**先查净额，再定性。**

### 17. 缺口是「某月独有」还是「每月都有」——**逐月单边对照**，别只看当月

当报表口径与第三方系统（进销存／物料账）对不上，**先做逐月序列**，再决定往哪查。构造一条"应当逐月成立"的单边恒等式：

```
对 M = 1..12：   |主科目(FAGLFLEXT, M)| − 辅助科目(FAGLFLEXT, M)   vs   对方系统(M)
```

- 若各月差都在**元级**、只有某一个月跳到十万级 → 缺口**完全由该月的月末凭证批次造成**，别去查科目映射、别去查长期政策。直接锁定该月所有"非业务类"凭证（抬头含「调整／还原／转移／尾差」、BLART 异常如 `Y6`/`SA`、参考过程 `AUAK`/`BKPF` 等）。
- 若各月差**同号且等比** → 是口径/映射系统性问题，改查配置。

实测序列（同案例）：1–8 月差 10,446.13 / 0.04 / −6,079.82 / 0.44 / −76.81 / 120.21 / −0.08 / 20.72，**9 月骤升 198,279.07** → 一句话锁定"9 月月末批次"。

**推论：月初不要急于"改报表公式"，先把缺口按月分层。**

### 18. 拆月内调整：把大额调整逐笔摆成**「+ / − / +」可复算桥**，并接受"轧差项"存在

月末批次常有多条独立链路（FI 结算 vs 自建还原程序），彼此不会逐笔配对。正确做法是**给出可复算的桥**，而不是硬找"某一张凭证"：

```
A（主科目明细贷方净额）
− 对方系统金额 − 辅助科目增加额
= 缺口
缺口 = ±轧差项(两条链路之差) ∓ 转移类凭证 ± 尾差类凭证
每项必须标出：金额 · 凭证号 · 对手科目 · 性质（业务/搬运/尾差）
```

实测：`101,634.96 = +190,686.43（3200152840+Y3 ↔ 3200152842 轧差）− 94,134.24（3200152841 FLT） + 5,082.83（1100228938 SA 尾差）`。

**交付话术**：把最后的轧差项明确写成"两条月结链路（FI 生产成本转出 vs 自建库存科目还原）的差额"，并给出"要拆到凭证行，需索要 X、Y 两张凭证完整分录"——**留一个明确的下一步，而不是含糊过去。**

**★ 报告口径与账面差 0.06 之类的小数**：若第三方报表（进销存/物料账）按物料级舍入，与总账汇总会有分位差。**在交付物里显式标注该差为舍入**，不要为了凑平而隐藏。

## 实战五：怎么把 ACDOCA 行项目明细导出来（写给用户的操作指引）

需要核对某段科目、但手上只有 FAGLFLEXT 总计表时，就得让用户补导**行项目明细**。给指引时套下面模板，别让用户自己猜。

### 1. 先认「用户手上那份明细是怎么导的」

SAP GUI 从 ALV 报表用「系统 → 列表 → 导出 → 本地文件 → 电子表格」导出的文件，特征是：

- 扩展名 `.XLS`，实际是 **GBK 编码 + Tab 分隔纯文本**（`file` 报 ISO-8859 text）
- 表头是**中英文对照 + 技术字段名**，如 `总账 (HKONT)`、`凭证抬头文本 (BKTXT)`、`抵销科目 (GKONT)`、`期间 (FISCPER)`

认出这个后，**最省事的指引 = 让用户复用同一入口/报表，只改筛选条件**，不用教他走新事物码。

### 2. 两套入口，按用户工具能力给

| 方案 | 入口 | 适用 |
|---|---|---|
| A（首选，最省事） | 复用用户上次导明细的**同一个报表/入口**，只把「总账科目」从单值改成**区间** | 该入口支持科目区间时 |
| B（通用兜底） | `SE16N` → 表 `ACDOCA` → 按条件筛选后导出 | 入口不支持区间、或用户想直查 |

FAGLL03H / FAGLL03（总账行项目）同样能按科目区间+期间出明细，字段够用。

### 3. 筛选条件模板（直接抄）

```
RLDNR   = 0L              账
RBUKRS  = <公司代码>       如 LNT
GJAHR   = <年>             如 2026
FISCPER = <YYYY.0MM>      如 2026.009    （或 POPER = 9）
RACCT   = <科目下限>–<科目上限>   用「多项选择 → 区间」
```

**★ 前导零坑**：工具里填 8 位（`7200000–7399999`）若查不到数据，改 10 位（`0072000000–0073999999`）。ACDOCA 的 `RACCT` 是 CHAR10，`7200000` 会被补成 `0007200000`，与 `0072000000` 不是一回事。

**一次导多段**：若工具支持，把区间开大（如 `0072000000–0073999999` 一次覆盖 0072+0073），导出后按科目前 4 位在本地拆，少操作一轮。

### 4. 必须勾的输出字段（定位「漏收」的关键）

- `BELNR` 凭证号 · `HKONT` 科目 · `SHKZG` 借贷标 · `CURRVAL_10` 公司代码货币值（↔ HSL）
- `BKTXT` 凭证抬头 · `SGTXT` 行项目文本 —— 找业务性质
- `GKONT` 抵销科目 —— 还原内部对转，**这条最有价值**
- `TCODE` · `USNAM` · `BUDAT` · `BLART`

### 5. 交付前先算好「基准金额」给用户当锚

别只说"你去导"。**先把目标段在 FAGLFLEXT 里的应有金额算出来**告诉用户：他导完能立刻自查，你拿到也能立刻对撞。

```
0072 人工段   9月 = 5,270,029.17   (16 个科目)
0073 制造费段 9月 = 6,534,954.56   (33 个科目)
两段合计          = 11,804,983.73
```

（逐月也一起给，便于判断"是不是只有某月异常"。）

### 6. 顺手把「未来要用的段」一并索要

定位一个缺口往往要查多个段。给指引时直接列全，省一次来回：

> 若方便，顺带导出 WIP段 `0012110000–0012119999` 和 项目70段 `0078010300–0078010999`，
> 我一次把四条可能路径全部排掉。

# 实战四：用 ACDOCA 行项目核对 FAGLFLEXT 总计表

> 主册：[`../SKILL.md`](../SKILL.md)。18 个小节是一条完整链路：
> 解析（GBK 假 XLS）→ 关键列 → 借贷分列对比 → 凭证腿平衡 → 镜像科目校验 →
> 干净段排除法 → 「漏收型 / 口径型」定性 → 可复算的月内调整桥。
> **每一步的结论都必须区分「已解释」和「未解释」，别为了结案把部分原因说成全部原因。**

场景：报表口径已经 100% 复现，但和另一个信息源差一个数，且汇总层穷举不到。
**下一步必然是拿行项目。** 用户导出的行项目常见形态是 **GBK 编码的 Tab 分隔文本，扩展名却是 `.XLS`**。

## 1. 解析（别被扩展名骗了）

```bash
file 123.XLS     # → ISO-8859 text, with CRLF line terminators   ← 不是真 XLS
```

```python
raw = open('123.XLS','rb').read().decode('gbk', errors='replace')
recs = [l.split('\t') for l in raw.split('\r\n')[1:] if l.strip()]
```

`openpyxl` / `xlrd` / `pandas.read_excel` 全部读不了。**先 `file` 探一下，再决定解析器。**

## 2. 关键列（SAP 行项目导出 31 列的 0 基序号）

| 序号 | 字段 | 用途 |
|---|---|---|
| 3 / 4 | BLART 凭证类型 / **BELNR 凭证号** | 定位到具体凭证 |
| 5 / 6 | HKONT 总账科目 / 科目短文本 | 确认科目名 |
| 7 | SHKZG 借贷（S/H） | **注意：S 也可能是负数**（借方红字） |
| 8 / 9 | KOSTL 成本中心 / 文本 | `99999 公共` = 结转类 |
| 11 / 14 | CURRVAL_0D 凭证货币 / **CURRVAL_10 公司代码货币** | 通常取 14 |
| **15 / 16** | **BKTXT 凭证抬头 / SGTXT 文本** | **业务性质，最关键的线索** |
| 18 | BUDAT 过账日期 | 时点 |
| 26 / 28 | TCODE / USNAM | 哪个程序、谁做的 |
| **29** | **GKONT 抵销科目** | **对方科目，用于还原完整分录** |

## 3. 核对姿势：借贷分列对比，定位断裂在哪一侧

**别只比净额。** 把总计表和行项目分别按「正值合计 / 负值合计」列出：

```
                    借方(S)              贷方(H)            净额
ACDOCA 明细   261,177,269.09      -2,137,282.44     259,039,986.65
FAGLFLEXT     261,177,269.09      -2,040,638.39     259,136,630.70
差 异                   0.00         -96,644.05         -96,644.05
```

**借方两侧完全一致、差异全在贷方** → 立刻知道是「某笔贷方/红字凭证没进总计表」，
而不是「口径整体偏移」。再去行项目里找那笔金额 = 96744.05 的凭证，一击即中。

> 陷阱：SAP 的 **SHKZG='S' 但金额为负** 的行（借方红字），按净额汇总时会"看起来"在借方，
> 实际等效于贷方。**必须先按金额正负分组，再和总计表比。**

## 4. 用 BKTXT 找业务性质

本例一次性命中：`BKTXT = '委托加工MPC调整'`。**凭证抬头是最有信息量的字段**，
比参考过程（BKPFF/MLHD）更能说明"这笔到底是干什么的"。

按 BKTXT / SGTXT 分组汇总，通常能立刻看出：
- 主业务（大额、单笔）
- 调整/冲销（成对正负、净 0）
- 分摊（成对红冲、净 0）
- 纯数量行（金额 0，如货物移动 WA 类型）

## 5. 全局反向搜索：拿差额去 FAGLFLEXT 里搜

行项目给的差额（如 96,644.05）**回到 FAGLFLEXT 全表搜**——如果只在某个陌生科目上命中一次，
那个科目往往就是答案的另一条腿（本例命中 `0012130701` 原材料库存，且**上个月也有一笔近似金额**，
说明是新业务，可据此判断"什么时候开始出问题"）。

> 搜「某科目某月一笔、上月一笔近似金额」是判断**新业务引入时点**的好办法。

## 6. 结论必须区分「已解释」和「未解释」

本例：找到 96,644.05，但差额是 198,279.01 —— **只解释 48.7%**。
**绝不能写成"找到原因了"。** 正确写法：

- 已定位：96,644.05（凭证 3200152844 / 3200152860，总计表少了后者）
- 修正后剩余：101,634.96，仍未定位，落在 0072/0073/WIP/0078 段之一
- 下一步：要凭证 3200152844/3200152860 的**完整分录（所有科目）** + 剩余段的明细

## 7. 拿到凭证完整分录后：做「收录情况」四象限对比

行项目只给你**一个科目**的腿。要判定"是整张凭证没进总计表，还是只有一条腿没进"，
需要让对方补**该凭证的完整分录（所有科目）**，然后逐个科目对比：

| 科目 | ACDOCA 明细 | FAGLFLEXT | 差 | 说明 |
|---|---|---|---|---|
| 71010101 原材料成本 | 两张 +/− 各一 | 含 +96,644.05 一笔 | -96,644.05 | 总计表只收了一张 |
| 78010101 生产成本归集 | 两张对冲，净 0 | 含 -96,644.05 一笔 | +96,644.05 | 同上 |
| 12130701 委托加工生产 | 两张对冲，净 0 | 仅 +96,644.05 一笔 | -96,644.05 | 同上 |
| 12130309 原材料账户结转 | 两张对冲，净 0 | 含 -96,644.05 一笔 | +96,644.05 | 镜像成立 |

**四个科目同向差同额 → 整张凭证（4 条腿）都没进总计表**，而不是某条腿的问题。结论要写清楚。

## 8. 镜像科目 = 免费的完整性校验（强烈推荐）

自建报表体系里常有**镜像科目对**（数值逐月严格相等、符号相反）。本例：

```
FAGLFLEXT 9月:  0071010101 = +259,136,630.70
                0012130309 = -259,136,630.70   ← 严格镜像
FAGLFLEXT 9月:  0071010101 = +259,136,630.70   （含 +96,644.05）
                ACDOCA      = +259,039,986.65   （含 +96,644.05 和 -96,644.05）
```

**用法**：先验证镜像在两套口径下是否都成立。若某月镜像被破坏，就是"某一条腿漏收"的铁证。
本例另一个例子：`0012130701` 在 FAGLFLEXT 里**只有 +96,644.05、没有对应的冲销**，
而行项目里明明有两笔对冲 —— 一眼就能看出总计表漏收。

> 实战价值：**搜一个可疑金额，命中唯一科目后，去看该科目有没有「该出现的反方向金额缺席」**。
> 缺席 = 漏收。

## 9. 结论必须沿用「已解释 / 未解释」两段式

拿完全部分录后的最终写法：

- **已定位**：96,644.05（整张 3200152860 未进总计表，4 条腿全缺）→ 0071 段虚增 → 项目75 虚增同额
- **修正后**：项目75 = 269,960,412.57 − 96,644.05 = 269,863,768.52
- **仍未定位**：101,634.96（FAGLFLEXT 全表扫 101,634.96 / 4,990.91 / 5,026.48 / 193,252.53 均 0 命中）
  → 必落在 0072/0073/WIP/0078 段，需那些段的行项目

**不要为了"结案"把 96,644.05 说成全部原因（它只占 48.7%）。**

## 10. 拿到新段明细后：先做「干净段排除法」，再用恒等式代数改写收缩残差

**目标**：一个缺口定位到某一段后，下一步是**排除**，而不是"再列一个可能原因"。

**第一步：严格对撞（比总额多两层）**

不要只看"总额对不对"。三层都过才算干净：

1. **总额**：明细合计 vs FAGLFLEXT 合计
2. **借贷分列**：明细 S/H 合计 vs FAGLFLEXT 按 DRCRK 分列的 S/H 合计
3. **逐科目**：每个科目的明细合计 vs FAGLFLEXT 该科目合计

> 案例：0072/0073 段三层全 0.00（借 34,717,038.37 / 贷 -22,912,054.64）→ **彻底排除，不用再看**。

**第二步：口径先选对，再谈差异**

同一份明细常有多列金额（凭证货币 `CURRVAL_0D` vs 公司代码货币 `CURRVAL_10`）。
**必须用与目标表同本位币的那一列**（FAGLFLEXT 的 HSL ↔ `CURRVAL_10`）。

> 案例：0072 段两种口径都对，0073 段**只有** `CURRVAL_10` 对（`CURRVAL_0D` 差 -66,365.85，是外币折算）。**口径选错会误判成"差异"。**

**第三步：把报表公式改写成"更少科目"的等价式**

原式项多（项目63 = 三段之和），不利于定位。找一条**科目更少**的代数等价式：

> 案例：`项目75 = |78010101 生产成本转出| − 0012110301(WIP)`
> 只涉及 2 个科目，一眼看出 269,960,412.57 = 270,821,508.91 − 861,096.34。

**第四步：把缺口写成"两侧科目之差"，缩小候选**

> 案例：`|78010101| − 0012010301(产成品入库) − 0012110301(WIP) = 198,279.07`
> 含义："生产成本转出的钱，比产成品入库 + WIP 多 X"。
> 再用双证排除某一侧（0012010301 已被总账 + 进销存双证）→ 候选只剩 2–3 个科目。

**第五步：交付"下一份要导的明细"**

不要笼统说"再查查看"。给出**具体科目 + 具体分组维度**：

> "导 `78010101` 的 9 月明细，按 `GKONT`（抵销科目）分组 → 看 X 转去了哪里。"

这样每轮都收敛，不会原地打转。

## 11. 判定"某科目有无额外漏收"：看借方是否精确 + 手工调整凭证

**判据（快）**：把 ACDOCA 明细与 FAGLFLEXT 做借贷分列对比。

- 若**借方完全相等、差异全在贷方且恰等于某个已知金额** → 该科目只有那一笔漏收，**无额外漏收**。

> 案例：78010101 借方两侧都 516,187.86；贷方差恰 +96,644.05，与 71010101 侧的 -96,644.05 **互为镜像** → 同一张凭证两条腿，双重证实，无额外漏收。

**残余缺口的头号嫌疑：`BKTXT` 非空的"手工调整凭证"**

标准业务（结转 ZCOR012、结算 CO88）之外，`BKTXT` 非空的行往往是月末手工调整：

- `重分类调整凭证`（新增走 ZCOR001，冲销走 FB08）
- `FLT.Cost Misc. Transfer`
- `结算费用尾差调整`

**做法**：把 `BKTXT` 非空的行单独列出，算净额，看是否落在"缺口"量级。

> 案例：9 月手工调整净 +115,022.69，与残余缺口 101,634.96 同量级 → 嫌疑最大。

**兜底判据**：若全局扫描（单科目、两科目加减）对缺口值 **0 命中**，说明缺口是**多凭证复合效应**，不是某个科目余额 —— 此时只能拿到"对方科目"明细才能拆。

## 12. 用「入账凭据分组」反推科目真实构成，并与第三方系统闭环

**手法**：拿到某科目的行项目明细后，**按 `BKTXT`（凭证抬头）分组**，往往一眼看出该科目当月由哪几类业务构成。

> 案例：产成品 `0012010301` 的 BKTXT 分组只有两类：
> - `2026.09库存科目还原` 269,302,637.21（1 行，凭证 3200152842）
> - `重分类调整凭证` 净 459,496.29（13 行：FB08 冲销 +3,808,233.21 / ZCOR001 -3,348,736.92）
> → 净额 269,762,133.50 = 269,302,637.21 + 459,496.29。

**再与第三方报表闭环**：若另一个系统（进销存 ZCOR007N / 物料分类账 ZTCO017）也报同一个数，就用上面的分解去对：

> 案例：ZTCO017 的「总入库金额」269,302,637.21 = 库存科目还原；「接收差额」269,762,133.56 = 产成品净额；两者之差 459,496.35 = 重分类调整。
> **→ 修正了此前"差额是材料价格差异"的误判。** 差额的真相必须到对方系统里找对应的手工调整凭证，**不能按名字猜**（正呼应本文「不要按标签猜」的核心原则）。

**要点**：`BKTXT` 非空的行 = 手工 / 调整业务，是解释口径差的第一手材料；把它们单独列出来看净额，比推测快得多。

## 13. 全段排除后的收口：区分「漏收型」与「口径型」差异

**当所有相关段都通过三层对撞（差 0.00）后，不要再找"下一笔错"。** 结论应改写为：

> 差异 = ① 已定位的漏收（若有）+ ② 口径型楔子（非账证错误）

**判据**：

- 三层对撞**有差** → **漏收型**（账上确实少记 / 多记）→ 继续追凭证
- 三层对撞**全 0 但报表仍不吻合** → **口径型**（两套报表定义不同）→ 找月末调整凭证 + 请业务确认口径

**口径型差异的定位手法**：把两侧的**月末手工调整凭证**（`BKTXT` 非空）列出来对齐。

> 案例：产成品侧 9 月有「库存科目还原」（3200152842）、「重分类调整」；生产成本侧有「FLT.Cost Misc. Transfer」「重分类调整」「结算费用尾差」。这些调整在科目间"搬运"金额，是口径差的来源。
> **验证搬运是否中性**：把调整在各科目间的净额相加，应 ≈ 0（案例：78010101 +25,971.28 / 产成品 +459,496.29 / WIP -485,467.57 = 0）。

**交付话术**：明确告诉用户"**这不是账记错了，是两个报表口径不同**"，并给出定量桥，避免无止境倒查。

> 案例终局：`项目75 269,960,412.57 − 进销存 269,762,133.56 = 198,279.01`，而
> `198,279.01 = 96,644.05（汇总表↔行项目不一致）+ 101,634.96（口径型）`——**两个分量性质不同，必须分开表述**，别把 198,279.01 整包说成"漏账"。

## 14. 凭证腿平衡检测：用「已见腿之和」找未见腿，并甄别残差真伪

**做法**：拿到某科目（或若干科目）的行项目明细后，按 `BELNR` 分组，把该凭证在**本文件里能看到的所有腿**相加。凭证必然借贷平衡，所以：

- 和 = 0 → 该凭证在本文件中的腿齐全（**注意：不能反推"凭证只有这几腿"**，见下方陷阱）
- 和 ≠ 0 → **有腿不在本文件里**（科目未导出），差额 = 未见腿净额

```python
from collections import defaultdict
g = defaultdict(float)
for r in rows:                 # rows = 某科目行项目明细
    g[r[4]] += float(r[14])    # col4=BELNR, col14=CURRVAL_10
for belnr, s in g.items():
    if abs(s) > 0.005:
        print(belnr, s)        # s = 未见腿净额（残差）
```

**陷阱**：和 = 0 **不等于**"凭证只有这些腿"。案例里 `3200152860` 在已导出的两个科目上恰好一正一负抵平（和 0），但它作为 `3200152844` 的镜像凭证，结构应当同构（4 腿）——另两腿落在未导出科目上。**判断凭证真实腿数，看它的镜像凭证。**

**用残差反查：必须做单行搜索甄别，别把算术量当漏账。**
把未见腿净额拿到「全部已导出明细 + 总计表」里做**单行搜索**：

- 命中 → 该笔真实存在，只是对应科目没导
- **0 命中 → 它只是"已见腿之和"这个算术量，不是任何一条真实分录** → 未见腿分散在多个科目，或该凭证的腿结构与你设想的不同；**必须去取完整凭证（按 `BELNR` 查 FB03 / ACDOCA），而不能继续按科目导**

> 案例：`450,461.51` / `271,442.60` / `536,867.47` 在全部已导出明细与总计表中 **0 命中** → 不可再当成"一笔漏账"去追，只能索要完整凭证。

## 15. 「总计表 vs 行项目」不一致：先排除分类账，再定性

**症状**：同一科目、同一期间的合计，`FAGLFLEXT`（总计表）与行项目明细对不上，且差额成对镜像。

**第一步永远是查 `RLDNR`**（行项目 0 基 `col1`）。若明细里混入了非取数分类账的行，而总计表口径是 `rldnr='0L'`，那"差额"只是**口径混样**，不是漏账。**必须全为 `0L` 才继续下结论。**

```python
from collections import defaultdict
d = defaultdict(lambda: [0, 0.0])
for r in rows:                       # col1=RLDNR, col14=金额
    d[r[1]][0] += 1; d[r[1]][1] += float(r[14])
# 期望：只有一个键 '0L'
```

**第二步：确认总计表本身是聚合表，不是凭证明细表。** `FAGLFLEXT` 的「对象编号」列（0 基 `1–9`）实测**全为 `0`**——它不含凭证号，行粒度 = 分类账 × 公司代码 × 科目 × 期间 × 借贷标识。因此：

- 表述上不能说"某张凭证没进总计表"，只能说"**总计表在某科目某方向上少了 X**"
- 对撞时必须先按 **科目 × 借贷方向** 聚合再比；行项目里同科目同方向的多行，在总计表里会被合并成一行，逐行比会误判

**第三步：镜像差额的成因表述。** 若 A / B 两科目出现 ±X 的严格反向差，且 X 对应某张红字冲销凭证（同额反向、同抬头、同日），正确表述是：

> 总计表未体现该红字凭证的冲销，导致 A 科目借方虚增 X、B 科目贷方虚增 X。

这属 **「汇总表与行项目不一致」**（汇总未刷新 / 反向凭证处理差异），需 SAP 侧核查（`FAGL_FCV` 重建汇总；FB03 查凭证过账与冲销状态），**不是业务做账错误**。

**第四步：用镜像科目对做旁证。** 若已知 `A ↔ A'` 为镜像科目对（严格 ± 相等），A 上出现 X 的差，则 A' 上应有 -X 的痕迹。

> 案例：`0012130309` 净 -259,136,630.70 ＝ `71010101` 净 +259,136,630.70 的相反数。

## 16. 「总计表 vs 行项目」差额的**端到端双层验证**（同一笔差异必须两处同额出现）

只在一侧发现 X 的差就下结论，容易冤枉。**同一笔红字/冲销凭证，应在「被冲销科目」与「对手科目」两侧各差 ±X，且都等于该凭证金额。** 做法：

```
对每个候选科目 A，同时算：
  A(FAGLFLEXT 汇总)  vs  A(行项目明细导出)  →  差 dA
若 dA == 某凭证金额 X，再到其对手科目 B 上验证 dB == ∓X。
两处都命中 → 结论成立（汇总表未落该凭证）。
```

实测案例（某客户 LNT 2026-09）：`71010101` 汇总 259,136,630.70 − 明细(`123.XLS`) 259,039,986.65 = **96,644.05**；`78010101` 汇总 −270,821,508.91 − 明细(`78010101.XLS`) −270,724,864.86 = **96,644.05**，方向相反。两处都等于委托加工 MPC 调整凭证 3200152844 的金额 → 强行坐实「3200152860 红字腿未进汇总表」。

**★ 关键前提：明细导出必须"两腿都在"。** 判据是看明细里该抬头/凭证的**净额为 0**（如 `Y4 委托加工MPC调整 2 行 0.00`）。若明细只有一条腿，那差额是明细不完整，不是汇总表问题——结论完全相反。**先查净额，再定性。**

## 17. 缺口是「某月独有」还是「每月都有」——**逐月单边对照**，别只看当月

当报表口径与第三方系统（进销存／物料账）对不上，**先做逐月序列**，再决定往哪查。构造一条"应当逐月成立"的单边恒等式：

```
对 M = 1..12：   |主科目(FAGLFLEXT, M)| − 辅助科目(FAGLFLEXT, M)   vs   对方系统(M)
```

- 若各月差都在**元级**、只有某一个月跳到十万级 → 缺口**完全由该月的月末凭证批次造成**，别去查科目映射、别去查长期政策。直接锁定该月所有"非业务类"凭证（抬头含「调整／还原／转移／尾差」、BLART 异常如 `Y6`/`SA`、参考过程 `AUAK`/`BKPF` 等）。
- 若各月差**同号且等比** → 是口径/映射系统性问题，改查配置。

实测序列（同案例）：1–8 月差 10,446.13 / 0.04 / −6,079.82 / 0.44 / −76.81 / 120.21 / −0.08 / 20.72，**9 月骤升 198,279.07** → 一句话锁定"9 月月末批次"。

**推论：月初不要急于"改报表公式"，先把缺口按月分层。**

## 18. 拆月内调整：把大额调整逐笔摆成**「+ / − / +」可复算桥**，并接受"轧差项"存在

月末批次常有多条独立链路（FI 结算 vs 自建还原程序），彼此不会逐笔配对。正确做法是**给出可复算的桥**，而不是硬找"某一张凭证"：

```
A（主科目明细贷方净额）
− 对方系统金额 − 辅助科目增加额
= 缺口
缺口 = ±轧差项(两条链路之差) ∓ 转移类凭证 ± 尾差类凭证
每项必须标出：金额 · 凭证号 · 对手科目 · 性质（业务/搬运/尾差）
```

实测：`101,634.96 = +190,686.43（3200152840+Y3 ↔ 3200152842 轧差）− 94,134.24（3200152841 FLT） + 5,082.83（1100228938 SA 尾差）`。

**交付话术**：把最后的轧差项明确写成"两条月结链路（FI 生产成本转出 vs 自建库存科目还原）的差额"，并给出"要拆到凭证行，需索要 X、Y 两张凭证完整分录"——**留一个明确的下一步，而不是含糊过去。**

**★ 报告口径与账面差 0.06 之类的小数**：若第三方报表（进销存/物料账）按物料级舍入，与总账汇总会有分位差。**在交付物里显式标注该差为舍入**，不要为了凑平而隐藏。
